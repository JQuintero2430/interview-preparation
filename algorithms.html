01

Two Pointers

La idea central de este patrón es recorrer un arreglo desde dos extremos simultáneamente para evitar una segunda pasada. En lugar de probar todas las combinaciones posibles con dos bucles anidados (O(n²)), se toma una decisión inteligente en cada paso para mover uno de los dos punteros.

Pregunta mental: "¿Puedo mover un extremo y saber cómo cambia el resultado sin revisar todo de nuevo?"

Cuándo identificarlo

El enunciado del problema menciona alguna de estas palabras clave: arreglo ordenado, pares con suma objetivo, palíndromos, mover ceros, contenedores de agua. Si el problema trabaja sobre elementos en posiciones opuestas y se puede tomar una decisión binaria (mover izquierda o mover derecha), es Two Pointers.

Ejemplo clásico — Two Sum en arreglo ordenado

Dado el arreglo [1, 2, 3, 4, 6, 8, 11] y un objetivo de 10, se inicia con un puntero al inicio y otro al final. Si la suma es mayor al objetivo, se mueve el puntero derecho hacia adentro; si es menor, se mueve el izquierdo. Nunca se vuelve atrás. 

int left = 0;
int right = arr.length - 1;

while (left < right) {

    int sum = arr[left] + arr[right];

    if (sum == target) {
        return true;
    }

    if (sum < target) {
        left++;
    } else {
        right--;
    }
}
Tiempo: O(n)  ·  Espacio: O(1)

Sliding Window

Este patrón resuelve el problema de recalcular todo desde cero en cada iteración. En lugar de eso, se mantiene una "ventana" activa que se desliza por el arreglo: se agrega el nuevo elemento que entra por la derecha y se quita el que sale por la izquierda. El trabajo ya hecho no se repite.

Pregunta mental: "¿Estoy recalculando demasiadas veces? ¿Puedo reutilizar la suma o el estado de la iteración anterior?"

Cuándo identificarlo

El enunciado menciona: subarray, substring, tamaño k, máximo o mínimo consecutivo, suma continua. Si la respuesta se construye sobre elementos contiguos y se está tentado a usar dos bucles anidados, la solución es Sliding Window.

Existen dos variantes. La ventana fija (fixed window) trabaja con un tamaño predefinido k. La ventana dinámica expande la ventana hacia la derecha y la contrae por la izquierda cuando se viola alguna condición.

Plantilla Fixed Window

int sum = 0;

// Inicializar la primera ventana
for (int i = 0; i < k; i++)
    sum += arr[i];

// Deslizar la ventana
for (int i = k; i < arr.length; i++) {
    sum += arr[i];       // entra el nuevo
    sum -= arr[i - k];   // sale el viejo
}

Plantilla Dynamic Window

int left = 0;

for (int right = 0; right < s.length(); right++) {

    // Expandir: procesar s.charAt(right)

    while (ventanaInvalida) {
        // Contraer desde la izquierda
        left++;
    }
}
Tiempo: O(n)  ·  Espacio: O(1) o O(k)

03

Prefix Sum

El Prefix Sum consiste en precalcular sumas acumuladas para poder responder consultas sobre rangos en tiempo O(1). En lugar de sumar los elementos de un rango cada vez que se necesite, se construye un arreglo auxiliar donde cada posición contiene la suma de todos los elementos desde el inicio hasta ese punto.

Pregunta mental: "¿Necesito recordar el pasado eficientemente para responder preguntas sobre el futuro?"

Cuándo identificarlo

El enunciado pregunta por sumas entre rangos, conteo de subarrays que cumplen una condición, balanceo de elementos (0 y 1, pares e impares), o frecuencias acumuladas. Si el problema requiere revisar muchos rangos distintos sobre el mismo arreglo, Prefix Sum evita repetir trabajo.

Construcción base y consulta de rango

int[] prefix = new int[n];
prefix[0] = arr[0];

for (int i = 1; i < n; i++)
    prefix[i] = prefix[i - 1] + arr[i];

// Suma entre índices l y r (inclusive)
int range = prefix[r] - (l > 0 ? prefix[l - 1] : 0);

Variante con HashMap — Conteo de subarrays

La variante más poderosa en entrevistas combina Prefix Sum con un HashMap. La idea es: si en algún momento la suma acumulada hasta el índice actual menos K ya había aparecido antes, entonces existe un subarray de suma K. Se guarda en el mapa cuántas veces ha ocurrido cada suma acumulada. 

Map<Integer, Integer> map = new HashMap<>();
map.put(0, 1); // suma 0 ocurre una vez antes de empezar

int sum = 0, count = 0;

for (int num : nums) {
    sum += num;

    if (map.containsKey(sum - k))
        count += map.get(sum - k);

    map.put(sum, map.getOrDefault(sum, 0) + 1);
}
Tiempo: O(n)  ·  Espacio: O(n)

04

Kadane's Algorithm

Kadane resuelve el problema del subarray de suma máxima en O(n). La idea es simple pero elegante: en cada posición se decide si conviene extender el subarray actual o empezar uno nuevo desde ese elemento. Si el acumulado hasta ahora es negativo, es mejor abandonarlo, porque sumar un número negativo siempre perjudica la suma futura.

Pregunta mental: "Si el pasado me perjudica, lo abandono y empiezo de nuevo."

Cuándo identificarlo

El enunciado pregunta por: máximo subarray, máxima ganancia continua, mejor beneficio acumulado, o puntaje máximo a lo largo de una secuencia. La clave es que se busca el mejor resultado continuo, no una combinación arbitraria de elementos.

Implementación

Se recorre el arreglo manteniendo dos variables: current, que representa la mejor suma terminando en la posición actual, y best, que guarda el máximo global. En cada paso, se elige entre empezar desde cero con el elemento actual o extender el subarray previo. 

int current = nums[0];
int best    = nums[0];

for (int i = 1; i < nums.length; i++) {
    current = Math.max(nums[i], current + nums[i]);
    best    = Math.max(best, current);
}
Tiempo: O(n)  ·  Espacio: O(1)

Ejemplo paso a paso

Con el arreglo [-2, 1, -3, 4, -1, 2, 1, -5, 4], al llegar al 4 se abandona el acumulado negativo (-4) y se reinicia desde 4. Luego se extiende hasta 4, -1, 2, 1, produciendo la suma máxima de 6.

05

BFS — Breadth-First Search

BFS (búsqueda en anchura) explora un grafo capa por capa: primero todos los nodos a distancia 1, luego los de distancia 2, y así sucesivamente. Esta propiedad lo hace el algoritmo correcto para encontrar el camino más corto en un grafo no ponderado.

Regla de oro: si el problema pide el mínimo número de pasos o la distancia más corta en un grafo sin pesos, la respuesta es BFS, siempre.

Cuándo identificarlo

Las palabras clave son: mínimo número de pasos, distancia más corta, movimientos por turnos, expansión simultánea (como naranjas pudriéndose o fuego propagándose), recorrido nivel a nivel, o cualquier problema sobre matrices donde se deba llegar de un punto a otro con el mínimo de movimientos.

Es importante entender que muchos problemas de matrices son grafos implícitos. Cada celda es un nodo y sus vecinos son los nodos adyacentes. No hace falta que el problema diga "grafo" para usar BFS.

Plantilla BFS sobre matriz

int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};

Queue<int[]> q = new LinkedList<>();
boolean[][] visited = new boolean[m][n];

q.add(new int[]{startX, startY});
visited[startX][startY] = true;

int steps = 0;

while (!q.isEmpty()) {

    int size = q.size(); // tamaño del nivel actual

    for (int i = 0; i < size; i++) {

        int[] node = q.poll();
        int x = node[0], y = node[1];

        if (esObjetivo(x, y)) return steps;

        for (int[] dir : dirs) {
            int nx = x + dir[0];
            int ny = y + dir[1];

            if (valido(nx, ny) && !visited[nx][ny]) {
                visited[nx][ny] = true;
                q.add(new int[]{nx, ny});
            }
        }
    }

    steps++; // termina un nivel, avanza un paso
}

El detalle clave está en el bucle interno: se procesa exactamente el tamaño del nivel actual (q.size()) antes de incrementar los pasos. Esto garantiza que steps representa la distancia real desde el origen.

DFS con Stack — Iterativo

DFS (búsqueda en profundidad) explora un camino hasta el final antes de retroceder y probar otro. Mientras BFS piensa en capas, DFS piensa en rutas completas. Su versión iterativa usa un stack explícito en lugar de recursión, lo que evita StackOverflow en grafos grandes.

Pregunta mental: "¿Necesito explorar todos los caminos posibles, detectar ciclos, o determinar si algo es alcanzable?"

Cuándo identificarlo

Se usa DFS cuando el problema requiere: explorar todos los nodos de un componente, detectar ciclos en un grafo, hacer backtracking, validar si existe un camino (sin importar la distancia), o procesar la estructura de un árbol. A diferencia de BFS, DFS no garantiza el camino más corto.

Diferencia fundamental con BFS

La única diferencia estructural en el código es la estructura de datos: BFS usa una Queue (FIFO, primero en entrar, primero en salir), que produce exploración por niveles. DFS usa un Stack (LIFO, último en entrar, primero en salir), que produce exploración en profundidad. Todo lo demás es casi idéntico.

Plantilla DFS iterativo

Stack<int[]> stack = new Stack<>();
boolean[][] visited = new boolean[m][n];

stack.push(new int[]{startX, startY});

while (!stack.isEmpty()) {

    int[] node = stack.pop();
    int x = node[0], y = node[1];

    if (visited[x][y]) continue; // puede haberse encolado dos veces
    visited[x][y] = true;

    if (esObjetivo(x, y)) return true;

    for (int[] dir : dirs) {
        int nx = x + dir[0];
        int ny = y + dir[1];

        if (valido(nx, ny) && !visited[nx][ny])
            stack.push(new int[]{nx, ny});
    }
}

Floyd's Tortoise and Hare

Este algoritmo detecta ciclos en una secuencia usando solo dos punteros y espacio O(1). A primera vista parece un algoritmo sobre arrays, pero en realidad modela un linked list implícito donde cada valor es un puntero al siguiente nodo.

La clave conceptual: cada elemento del arreglo no es un dato, es un puntero. El valor en la posición i apunta a la posición nums[i].

El problema que resuelve

Dado un arreglo de n+1 números en el rango [1..n], donde exactamente uno está duplicado, hay que encontrar ese duplicado sin modificar el arreglo y usando espacio constante. La solución ingenua usaría un HashSet (O(n) espacio) o modificaría el arreglo. Floyd lo hace en O(1) espacio.

Modelando el linked list

Con el arreglo [1, 3, 4, 2, 2], se puede construir la cadena de punteros: empezando en el índice 0, su valor es 1, entonces se va al índice 1, cuyo valor es 3, luego al índice 3, cuyo valor es 2, luego al índice 2, cuyo valor es 4, luego al índice 4, cuyo valor es 2... y aquí empieza el ciclo entre los índices 2 y 4. El número que forma el ciclo es el duplicado.

Fase 1 — Detectar que existe el ciclo

Se usan dos punteros: slow avanza un paso (sigue el puntero una vez) y fast avanza dos pasos. Dado que hay un ciclo, eventualmente se encontrarán. Este punto de encuentro no es la entrada del ciclo, solo confirma su existencia. 

int slow = nums[0];
int fast = nums[0];

do {
    slow = nums[slow];
    fast = nums[nums[fast]];
} while (slow != fast);

Fase 2 — Encontrar la entrada del ciclo (el duplicado)

Aquí ocurre lo matemáticamente elegante. Cuando los dos punteros se encuentran, uno de ellos se reinicia al inicio del arreglo y ambos avanzan un solo paso a la vez. El punto donde vuelven a encontrarse es exactamente la entrada del ciclo, que es el número duplicado.

La razón es geométrica: si se llama a a la distancia desde el inicio hasta la entrada del ciclo, b a la distancia desde la entrada hasta el punto de encuentro, y c al resto del ciclo, entonces cuando chocan, fast recorrió el doble que slow. Resolviendo la ecuación, slow está exactamente a a pasos de la entrada, lo mismo que el inicio del arreglo. 

slow = nums[0]; // se reinicia al inicio

while (slow != fast) {
    slow = nums[slow];
    fast = nums[fast]; // ahora ambos van a 1 paso
}

return slow; // este es el duplicado
Tiempo: O(n)  ·  Espacio: O(1)

Cuándo reconocerlo en entrevista

Aparece cuando el enunciado combina: números en rango [1..n], arreglo de tamaño n+1, encontrar el duplicado, no modificar el arreglo, y espacio constante. Si están presentes esas cuatro condiciones juntas, casi con certeza es Floyd Cycle Detection.

Monotonic Stack — Stock Span

El problema del Stock Span introduce uno de los patrones más poderosos de entrevistas: el Monotonic Stack. La intuición detrás es que cuando aparece un elemento mayor que los anteriores, esos elementos anteriores jamás volverán a ser relevantes para ningún elemento futuro. Se pueden descartar permanentemente.

Pregunta mental: "¿Hay elementos en el pasado que ya nunca volverán a importar porque el presente los domina?"

El problema

Dado un arreglo de precios diarios de una acción, para cada día se debe calcular cuántos días consecutivos hacia atrás el precio fue menor o igual al de hoy. Con el arreglo [100, 80, 60, 70, 60, 75, 85], el resultado es [1, 1, 1, 2, 1, 4, 6]. Para el precio 85, el span es 6 porque los seis días anteriores tuvieron precios menores o iguales.

Por qué funciona el stack

La solución ingenua compara cada día con todos los anteriores: O(n²). La mejora viene de observar que si hoy el precio es mayor que ayer, ayer nunca volverá a ser consultado por ningún día futuro (porque cualquier día futuro compara con hoy primero, y si hoy ya es mayor, ayer queda eclipsado). Esto significa que ayer puede eliminarse del stack.

El stack guarda pares (precio, span acumulado). El span acumulado de un elemento representa cuántos días consecutivos "engloba" ese elemento. Cuando se elimina un elemento del stack porque el precio actual es mayor, se suma su span al span del elemento actual.

Implementación

class StockSpanner {

    private Stack<int[]> stack = new Stack<>();

    public int next(int price) {

        int span = 1; // el día actual siempre cuenta

        while (!stack.isEmpty() && stack.peek()[0] <= price) {
            span += stack.pop()[1]; // absorber el span del día eliminado
        }

        stack.push(new int[]{price, span});
        return span;
    }
}

Evolución del stack paso a paso

precio 100  →  stack: [(100,1)]
precio  80  →  stack: [(100,1),(80,1)]
precio  60  →  stack: [(100,1),(80,1),(60,1)]
precio  70  →  70>=60, elimina (60,1), span=2
               stack: [(100,1),(80,1),(70,2)]
precio  75  →  75>=70, elimina (70,2); 75>=60, ya no está
               span = 1 + 2 = 3? No:
               75>=80? No. Detiene.  stack: [(100,1),(80,1),(75,4)]
               (el 4 viene de: 1 + suma de spans eliminados)
precio  85  →  85>=75 suma 4, 85>=80 suma 1 → span=6
               stack: [(100,1),(85,6)]

Cada elemento entra al stack una vez y sale una vez, por lo que el tiempo total es O(n) amortizado.

Tiempo amortizado: O(n)  ·  Espacio: O(n)

Cuándo reconocer Monotonic Stack en entrevista

Las palabras clave son: próximo elemento mayor, días hasta temperatura más alta, área en histograma, span o rango continuo, o cualquier situación donde se necesite eliminar elementos que han sido "dominados" por un elemento más grande o más reciente.

Kahn's Algorithm — Ordenamiento Topológico

Kahn resuelve el problema de ordenar tareas con dependencias. Si la tarea A debe completarse antes que la tarea B, ¿cuál es un orden válido para ejecutar todas las tareas? Si existe un ciclo (A depende de B y B depende de A), no hay orden válido posible.

Idea central: si algo no tiene ninguna dependencia pendiente, se puede hacer ahora. Completarlo puede desbloquear otras tareas.

El concepto de in-degree

El in-degree de un nodo es el número de aristas que llegan a él, es decir, cuántas dependencias tiene. Un nodo con in-degree 0 no tiene prerrequisitos y puede ejecutarse de inmediato. Al procesarlo, se reduce el in-degree de todos sus vecinos. Si alguno de ellos llega a 0, entra a la cola.

Algoritmo paso a paso

Primero se calcula el in-degree de cada nodo recorriendo todas las aristas. Luego se meten en la cola todos los nodos con in-degree 0. Se procesa la cola: se saca un nodo, se agrega al orden resultante, y se reduce el in-degree de sus vecinos. Si algún vecino llega a 0, se agrega a la cola. Al terminar, si el orden resultante no contiene todos los nodos, significa que hay un ciclo y no existe ordenamiento válido.

Implementación en Java

public List<Integer> kahnTopoSort(int n, List<List<Integer>> graph) {

    int[] indegree = new int[n];

    // Calcular in-degree de cada nodo
    for (int u = 0; u < n; u++)
        for (int v : graph.get(u))
            indegree[v]++;

    Queue<Integer> q = new LinkedList<>();

    // Meter nodos sin dependencias
    for (int i = 0; i < n; i++)
        if (indegree[i] == 0)
            q.offer(i);

    List<Integer> order = new ArrayList<>();

    while (!q.isEmpty()) {
        int node = q.poll();
        order.add(node);

        for (int neighbor : graph.get(node)) {
            indegree[neighbor]--;

            if (indegree[neighbor] == 0)
                q.offer(neighbor);
        }
    }

    // Si no se procesaron todos, hay ciclo
    if (order.size() != n)
        return new ArrayList<>();

    return order;
}
Tiempo: O(V + E)  ·  Espacio: O(V)

Diferencia con DFS Topológico

DFS también puede hacer ordenamiento topológico usando el orden postorden de la recursión. Kahn, al ser BFS, produce un orden que respeta los niveles de dependencias (primero lo que no tiene prerrequisitos, luego lo que dependía de eso). Kahn además detecta ciclos naturalmente como efecto secundario: si quedan nodos sin procesar al final, hay ciclo.

Cuándo reconocerlo en entrevista

Las palabras que deben activar este patrón son: prerequisites, course schedule, order of tasks, dependency resolution, build order, alien dictionary, o cualquier variante de "¿puedo completar todas las tareas?". Si hay un orden implícito entre elementos con dependencias, es Kahn o topological sort.

Binary Search

La búsqueda binaria descarta la mitad del espacio de búsqueda en cada paso, pasando de O(n) a O(log n). Su verdadero poder en entrevistas no está en buscar un valor dentro de un arreglo ordenado, sino en "buscar sobre la respuesta": cuando la respuesta vive en un rango numérico y se puede verificar si un candidato es válido, se hace binary search sobre ese rango.

Pregunta mental: "¿El espacio de posibles respuestas está ordenado de forma monótona? Es decir, ¿si un valor funciona, todos los mayores (o todos los menores) también?"

Cuándo identificarlo

El enunciado menciona: arreglo ordenado, encontrar un valor, primer o último elemento que cumple una condición, minimizar el máximo o maximizar el mínimo, o "¿cuál es el menor k tal que...?". Si se puede escribir una función booleana puede(x) que sea monótona (falsa, falsa, ..., verdadera, verdadera), es Binary Search.

Plantilla — límite izquierdo (lower bound)

int left = 0;
int right = n;          // rango de búsqueda [left, right)

while (left < right) {
    int mid = left + (right - left) / 2;

    if (puede(mid)) {
        right = mid;        // mid podría ser la respuesta, no lo descartes
    } else {
        left = mid + 1;     // mid no sirve, descártalo
    }
}

return left;            // primer valor que cumple la condición

Usar left + (right - left) / 2 en lugar de (left + right) / 2 evita el desbordamiento cuando los índices son grandes. La invariante clave: nunca descartar mid cuando podría ser la respuesta.

Tiempo: O(log n)  ·  Espacio: O(1)

Problemas de práctica

Dynamic Programming

La programación dinámica resuelve un problema descomponiéndolo en subproblemas más pequeños que se solapan, y guardando el resultado de cada uno una sola vez. Esto convierte una recursión exponencial (que recalcula los mismos casos una y otra vez) en una solución polinómica.

Pregunta mental: "¿La solución se construye a partir de soluciones a versiones más pequeñas del mismo problema, y esos subproblemas se repiten?"

Cuándo identificarlo

El enunciado pide: contar de cuántas formas, mínimo o máximo costo, "¿es posible alcanzar?", la subsecuencia más larga, particiones óptimas, o una elección óptima bajo restricciones. La señal más fuerte: se te ocurre una solución recursiva, pero el árbol de llamadas repite los mismos argumentos.

Las tres preguntas

Todo problema de DP se resuelve respondiendo tres cosas: cuál es el estado (qué representa dp[i]), cuál es la transición (cómo se calcula dp[i] a partir de estados anteriores) y cuál es el caso base.

Plantilla bottom-up (1D)

// dp[i] = mejor resultado considerando hasta el elemento i
int[] dp = new int[n + 1];
dp[0] = casoBase;

for (int i = 1; i <= n; i++) {
    // transición: combinar estados ya calculados
    dp[i] = Math.max(dp[i - 1], dp[i - 2] + valor[i]);
}

return dp[n];

Este ejemplo corresponde a House Robber: en cada casa se elige entre saltarla (dp[i-1]) o robarla y sumar lo mejor de dos casas atrás (dp[i-2] + valor[i]). El mismo esqueleto sirve para casi cualquier DP lineal.

Tiempo: O(n) a O(n·k)  ·  Espacio: O(n), a veces O(1)

Heap / Priority Queue

Un heap (montículo) mantiene siempre accesible el elemento mínimo o máximo en O(1), con inserción y extracción en O(log n). Es la estructura correcta cuando importa repetidamente "el más grande o el más pequeño de lo que llevo hasta ahora", sin necesidad de ordenar todo el conjunto.

Pregunta mental: "¿Necesito repetidamente el elemento más grande o más pequeño de un conjunto que va cambiando?"

Cuándo identificarlo

El enunciado pide: los K elementos más frecuentes o más grandes, el k-ésimo mayor, mezclar k listas ordenadas, la mediana de un flujo de datos, planificar tareas por prioridad, o extraer repetidamente el mínimo costo. El truco de top-K: para quedarte con los K mayores, usa un min-heap de tamaño K y descarta el menor cada vez que se pasa.

Plantilla — K-ésimo elemento más grande

// min-heap de tamaño k → al final quedan los k mayores
PriorityQueue<Integer> heap = new PriorityQueue<>();

for (int num : nums) {
    heap.offer(num);

    if (heap.size() > k)
        heap.poll();       // saca el menor, mantiene los k mayores
}

return heap.peek();        // la raíz es el k-ésimo mayor

Mantener el heap acotado a tamaño k hace que cada inserción cueste O(log k) en vez de O(log n), reduciendo el total a O(n log k). Para un max-heap en Java se usa new PriorityQueue<>(Collections.reverseOrder()).

Tiempo: O(n log k)  ·  Espacio: O(k)

Backtracking

El backtracking construye una solución de forma incremental y abandona un camino en cuanto deja de ser válido (poda), retrocediendo para probar otra opción. Es, en esencia, un DFS sobre el árbol de decisiones, con un patrón de tres pasos: elegir, explorar, deshacer.

Pregunta mental: "¿Necesito generar todas las combinaciones, permutaciones o subconjuntos posibles, o encontrar una configuración que cumpla ciertas restricciones?"

Cuándo identificarlo

Las palabras clave son: subsets, permutations, combinations, generar todas las soluciones, sudoku, N-Queens, word search, particiones. La frase reveladora suele ser "todas las formas de..." o "encuentra una asignación válida que...".

Plantilla — el patrón elegir / explorar / deshacer

void backtrack(List<Integer> current, int start) {

    resultado.add(new ArrayList<>(current)); // registrar estado válido

    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);               // elegir
        backtrack(current, i + 1);         // explorar más profundo
        current.remove(current.size() - 1); // deshacer
    }
}

El paso de "deshacer" es lo que diferencia el backtracking de un DFS común: al regresar de la recursión, se restaura el estado exacto que había antes de elegir, dejando el terreno limpio para la siguiente opción del bucle.

Tiempo: O(2ⁿ) a O(n!)  ·  Espacio: O(n) de profundidad

Trie — Árbol de prefijos

Un Trie almacena cadenas carácter por carácter, compartiendo los prefijos comunes entre palabras. Esto permite buscar una palabra o un prefijo en O(L), donde L es su longitud, sin importar cuántas palabras haya guardadas: el costo depende de lo que buscas, no del tamaño del diccionario.

Pregunta mental: "¿Estoy consultando muchas palabras que comparten prefijos, o necesito autocompletar y buscar por prefijo de forma eficiente?"

Cuándo identificarlo

El enunciado menciona: autocomplete, diccionario, búsqueda por prefijo, validar palabras contra un conjunto grande, búsqueda con comodines, o recorrer una matriz buscando muchas palabras a la vez (donde el Trie se combina con backtracking). Si el problema gira en torno a prefijos compartidos, es un Trie.

Estructura e inserción

class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isWord;
}

void insert(String word) {
    TrieNode node = root;

    for (char c : word.toCharArray()) {
        int i = c - 'a';

        if (node.children[i] == null)
            node.children[i] = new TrieNode();

        node = node.children[i];
    }

    node.isWord = true; // marca el fin de una palabra completa
}

La búsqueda de un prefijo es idéntica pero sin marcar isWord: se recorre carácter a carácter y, si algún hijo es null, el prefijo no existe. El flag isWord distingue una palabra completa ("app") de un simple prefijo de otra ("apple").

Insertar / buscar: O(L)  ·  Espacio: O(N·L)

Union-Find — Disjoint Set Union

Union-Find agrupa elementos en conjuntos y responde en tiempo casi constante dos preguntas: "¿están estos dos elementos en el mismo grupo?" y "une estos dos grupos". Con compresión de caminos y unión por tamaño, cada operación cuesta O(α(n)), donde α es la inversa de Ackermann, prácticamente una constante.

Pregunta mental: "¿Estoy uniendo cosas en grupos y preguntando repetidamente si dos elementos ya están conectados?"

Cuándo identificarlo

El enunciado trata de: componentes conectados que se forman de a poco, detectar un ciclo en un grafo no dirigido, contar provincias o islas, redes de amigos, cuentas que se fusionan, o construir un árbol de expansión mínima (Kruskal). Su ventaja sobre DFS es que procesa uniones que llegan una a una, en línea.

Implementación con compresión de caminos

int[] parent;

int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]); // compresión: apunta directo a la raíz

    return parent[x];
}

void union(int a, int b) {
    parent[find(a)] = find(b); // conecta las dos raíces
}

La compresión de caminos aplana el árbol en cada find: tras la primera consulta, los nodos apuntan casi directamente a la raíz. Contar cuántas raíces distintas quedan (find(i) == i) da el número de componentes conectados.

Por operación: O(α(n)) ≈ O(1)  ·  Espacio: O(n)

Dijkstra — Camino más corto con pesos

Dijkstra encuentra el camino más corto desde un origen en un grafo con pesos no negativos. Es la evolución natural de BFS: donde BFS asume que toda arista cuesta 1 y usa una cola normal, Dijkstra usa una cola de prioridad (min-heap) para expandir siempre el nodo con la menor distancia acumulada conocida.

Pregunta mental: "¿Es el camino más corto, pero ahora las aristas tienen pesos distintos entre sí?"

Cuándo identificarlo

El enunciado pide: camino o costo mínimo con pesos, tiempo mínimo para que una señal llegue a toda la red, esfuerzo mínimo en una matriz, o el vuelo más barato. La regla de decisión: pesos uniformes → BFS; pesos no negativos → Dijkstra; pesos que pueden ser negativos → Bellman-Ford.

Plantilla con cola de prioridad

// [distancia, nodo], ordenado por distancia ascendente
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
int[] dist = new int[n];
Arrays.fill(dist, Integer.MAX_VALUE);

dist[src] = 0;
pq.offer(new int[]{0, src});

while (!pq.isEmpty()) {
    int[] top = pq.poll();
    int d = top[0], u = top[1];

    if (d > dist[u]) continue;      // entrada obsoleta, ya hay algo mejor

    for (int[] e : graph.get(u)) { // e = [vecino, peso]
        int v = e[0], w = e[1];

        if (dist[u] + w < dist[v]) {
            dist[v] = dist[u] + w;      // relajación de la arista
            pq.offer(new int[]{dist[v], v});
        }
    }
}

La comprobación if (d > dist[u]) continue descarta entradas viejas de la cola: como no se pueden eliminar elementos intermedios de un heap, simplemente se ignoran cuando se sacan. Por eso Dijkstra falla con pesos negativos: asume que una vez fijada la distancia mínima de un nodo, ya no puede mejorar.

Tiempo: O(E log V)  ·  Espacio: O(V)

Intervals — Intervalos

Los problemas de intervalos casi siempre se resuelven ordenando primero por el inicio (a veces por el fin) y luego recorriendo una sola vez, decidiendo en cada paso si el intervalo actual se solapa con el anterior. Ordenar convierte un problema aparentemente O(n²) de comparar todos contra todos en uno de O(n log n).

Pregunta mental: "¿Tengo rangos con inicio y fin, y necesito fusionarlos, contar solapamientos, o insertar uno nuevo manteniendo el orden?"

Cuándo identificarlo

El enunciado menciona: merge intervals, insertar un intervalo, salas de reuniones (¿cuántas se necesitan?), solapamientos, o eliminar el mínimo de intervalos para que ninguno se cruce. Las señales son pares [inicio, fin], reuniones, calendarios y rangos que se solapan.

Plantilla — fusionar intervalos

// ordenar por inicio
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);

List<int[]> merged = new ArrayList<>();

for (int[] cur : intervals) {
    int last = merged.size() - 1;

    if (merged.isEmpty() || merged.get(last)[1] < cur[0]) {
        merged.add(cur);                        // no se solapa, entra nuevo
    } else {
        merged.get(last)[1] =
            Math.max(merged.get(last)[1], cur[1]); // extender el fin
    }
}

Tras ordenar por inicio, dos intervalos se solapan exactamente cuando el fin del último fusionado alcanza o supera el inicio del actual. Para contar salas de reuniones simultáneas, la variante es separar inicios y fines, ordenarlos por separado y barrer con dos punteros.

Tiempo: O(n log n)  ·  Espacio: O(n)

Greedy — Algoritmos voraces

Un algoritmo voraz toma en cada paso la decisión que parece mejor en ese momento, sin reconsiderar ni retroceder, y confía en que esa cadena de elecciones locales lleva al óptimo global. A diferencia de los demás patrones de esta guía, greedy no es una plantilla: es una estrategia cuya parte difícil no es el código, sino demostrar que la elección local nunca arruina el resultado final.

Advertencia: greedy es tentador porque casi siempre "parece" correcto. Antes de confiar en él, hay que justificar por qué la mejor decisión de ahora no bloquea una mejor solución después. Si no puedes argumentarlo, probablemente el problema es de DP.

Cuándo identificarlo

El enunciado pide maximizar o minimizar algo y existe un criterio natural de orden: procesar por el que termina antes, por el más caro, por el más cercano. Palabras clave: máximo número de actividades, mínimo número de saltos o monedas, repostar el mínimo de veces, asignar recursos. Si ordenar por algún atributo hace obvia la siguiente decisión, suele ser greedy.

Cómo saber si greedy es válido

Dos propiedades deben cumplirse: elección voraz (existe un óptimo global que incluye la elección local) y subestructura óptima (la solución del problema contiene soluciones óptimas de sus subproblemas). La técnica clásica de prueba es el argumento de intercambio: suponer una solución óptima distinta y mostrar que se puede cambiar por la voraz sin empeorarla.

Ejemplo — Jump Game (¿se puede llegar al final?)

En cada posición se guarda el índice más lejano alcanzable hasta ahora. Si en algún punto el índice actual supera ese alcance, quedaste atascado. No hay que probar cada salto: basta con extender el alcance de forma voraz. 

int alcance = 0;

for (int i = 0; i < nums.length; i++) {

    if (i > alcance) return false; // inalcanzable

    alcance = Math.max(alcance, i + nums[i]); // extender lo más lejos posible
}

return true;

Otro patrón voraz muy frecuente es sobre intervalos: para escoger el máximo de tareas no solapadas, se ordena por el tiempo de fin y se toma siempre la que termina antes, dejando el mayor espacio para las siguientes.

Tiempo: O(n) u O(n log n) si ordena  ·  Espacio: O(1)

Bit Manipulation — Manipulación de bits

La manipulación de bits no es un patrón único con plantilla, sino una caja de trucos que operan directamente sobre la representación binaria de los números. Sirve para conseguir soluciones en O(1) de espacio o para eliminar bucles, aprovechando que ciertas operaciones lógicas hacen en un paso lo que normalmente requeriría iterar.

Las operaciones base: & (AND), | (OR), ^ (XOR), ~ (NOT), << y >> (desplazamientos). La estrella en entrevistas es XOR, porque un número consigo mismo da 0 y con 0 se queda igual.

Cuándo identificarlo

El enunciado sugiere bits cuando pide: encontrar el número que aparece una sola vez mientras el resto está en pares, contar bits encendidos, generar todos los subconjuntos (una máscara por subconjunto), verificar si un número es potencia de dos, o intercambiar/sumar sin operadores aritméticos. También aparece cuando el rango de valores es pequeño y cabe en una máscara.

Trucos esenciales

// XOR cancela pares: el único sin pareja sobrevive
int unico = 0;
for (int n : nums) unico ^= n;

// ¿el bit i está encendido?
boolean on = (x & (1 << i)) != 0;

// encender / apagar el bit i
x = x | (1 << i);   // set
x = x & ~(1 << i);  // clear

// quita el bit encendido más bajo (útil para contar bits)
x = x & (x - 1);

// ¿potencia de dos? un solo bit encendido
boolean pow2 = x > 0 && (x & (x - 1)) == 0;

El truco x & (x - 1) apaga el bit encendido más a la derecha: repetirlo hasta que x valga 0 cuenta los bits activos en tantas iteraciones como bits haya, no como el ancho total del entero (algoritmo de Brian Kernighan).

Por operación: O(1)  ·  Recorrer bits: O(número de bits)
