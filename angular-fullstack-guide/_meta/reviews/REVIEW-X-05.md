#### X-05-F02 · Medium · contradiction (Summary vs owner) · 42's Summary says `csrf.spa()` masks the token

- **Location:** `modules/42-fullstack-authentication.md:1409` (Summary) "`csrf.spa()` masks the token, and logout clears it"; against the owner, 42 §6 mental model (42:766) "Spring by default expects a **masked token** …; script has the raw cookie, which **`csrf.spa()`** (`@since 7.0`) accepts", 42:791 "`SpaCsrfTokenRequestHandler`: a header is compared as sent", and Q42.17 "`spa()` (`@since 7.0`) accepts the raw header token"; and 43, which builds on it: 43:835 "`CONNECT` needs the **masked token** … unlike `csrf.spa()` on HTTP" and 43:1673 "unlike `csrf.spa()`".
- **Evidence:** the Spring Security reference (WebFetch, 2026-10-24) says BREACH masking is the default, that "JavaScript applications will only have access to the plain token value", and that `csrf.spa()` is the integration for that case. A `spa()` handler that only masked would not make Angular's raw `X-XSRF-TOKEN` copy pass. Masking is the default handler's behavior, and `spa()` is what relaxes it for the header. A reader who revises from the Summary alone learns the reverse of §6. That also makes 43's contrast ("unlike `csrf.spa()`") read as a contradiction.
- **Right side:** 42 §6, Q42.17 and 43.
- **Fix text:** 42, Summary: `` `csrf.spa()` masks the token, and logout clears it `` → `` `csrf.spa()` accepts the raw cookie value in the header, and logout clears it `` (+5 words; 42 → 9,836).
