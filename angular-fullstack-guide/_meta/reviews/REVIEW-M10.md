## Factual findings

**F-1 · Medium · "Once true in every browser" is not what MDN's date means (lines 161 and 224).**
- Location: line 161: "CSS cannot select a parent. *Once true in every browser: MDN dates `:has()` across browsers to December 2023.*"; line 224: "*Once true in every browser: subgrid was not available across browsers until September 2023 (MDN).*"
- Wrong: MDN's "across browsers since December 2023" is the date the last of the four Baseline browsers shipped. The MDN compat data (read) gives `:has()` Chrome 105, Safari 15.4, Firefox 121; subgrid Firefox 71, Safari 16, Chrome 117. So "CSS cannot select a parent" was false in Safari and Chrome from 2022, and subgrid was available in Firefox from 2019. The belief was true "across browsers", not "in every browser". STYLE-GUIDE §4.2.7 asks for "until which version", so the clause should say which.
- Correction: "Once true across browsers: `:has()` reached Firefox 121 in December 2023, the last Baseline browser (Safari and Chrome had it from 2022; MDN)." and "Once true across browsers: Chrome and Edge had no subgrid until 117, September 2023 (Firefox had it from 71; MDN)". The release dates of Chrome 105 and Safari 15.4 were not fetched (V-1): write version numbers, or read the dates first.
- Basis: read MDN browser-compat-data (`css/selectors/has.json`, `css/properties/grid-template-columns.json`), MDN `:has()` and subgrid pages. Not observed.

**F-2 · Medium · `container-type: inline-size` applies inline-size containment, not size containment (line 378, Q10.12 at 843, glossary).**
- Location: line 378 defines "**Size containment** means the box's size is computed as if it had no content ([Containment 3 §3.1](https://www.w3.org/TR/css-contain-3/#containment-inline-size))"; Q10.12 (843): "`container-type: inline-size` applies size containment (the container's width cannot come from its children)"; `GLOSSARY-TERMS.md` "size containment".
- Wrong: Containment 3 §4.1 (read): `size` "applies layout containment, style containment, and size containment"; `inline-size` "applies layout containment, style containment, and inline-size containment". §3.1, the section the module links, is "Inline-Size Containment": "the inline-axis intrinsic sizes of the principal box are determined as if the element had no content … content continues to impact the box's block-axis intrinsic sizes". The behavior sentence in the module is right for `inline-size`; the name and the definition (size, both axes) are not. `SOURCES.md` already says "inline-size applies layout, style and inline-size containment".
- Correction: define **inline-size containment** (the inline size ignores the content, the block size does not) and say `size` adds the block axis; fix Q10.12 and the glossary entry.
- Basis: read Containment 3 §3.1 and §4.1, MDN Container queries ("Applies layout, style, and inline-size containment").

**F-3 · Low-Medium · "widely available since <date>" misuses MDN's "across browsers since <date>" (lines 116, 376, 379, 444 twice, 560).**
- Wrong: the module defines widely available as "a consistent history of support in each [browser] for at least 2.5 years" (26). MDN's wording on every page read is "Widely available … available across browsers since March 2022" (or the other dates). "Widely available since July 2020" says the feature was widely available in July 2020; it became so 2.5 years later. Lines 195, 378, 775 and 986 use the correct form ("widely available, across browsers since …").
- Correction: use one form everywhere: "widely available (across browsers since March 2022; MDN)". Same for `prefers-color-scheme` and `color-scheme` at 444, nesting at 560, `clamp()` at 379, `@media` at 376, `@layer` at 116.
- Basis: read the MDN pages and the Baseline compatibility glossary page. Every date itself matches MDN.

**F-4 · Low-Medium · `@scope` adds a cascade round the six-round model leaves out (line 120, diagram at 94-108).**
- Wrong: line 120 says `@scope` "limits rules to a subtree"; MDN `@scope` (read) says it "adds a new criterion to the CSS cascade: scoping proximity … overrules source order but is itself overridden by … importance, layers, and specificity". So in a browser that supports `@scope` there are seven rounds, between specificity and order of appearance; the module's "Last in order of appearance" (round 6) and the Q10.03 answer ("then order of appearance") are the Cascade 5 model. The module names Cascade Level 5 only.
- Correction: add one clause at line 120: "`@scope` adds a proximity round between specificity and order of appearance (MDN; Cascade 6 draft); the six rounds here are Cascade 5". Cost about 20 words.
- Basis: read MDN `@scope`. Not observed (jsdom applies no `@scope`; pinned).

**F-5 · Low · "flex or grid margins never collapse" is wider than the sources (line 53, Q10.02 at 607).**
- Wrong: Flexbox 1 §3 (read): "the flex container's margins do not collapse with the margins of its contents"; "the margins of adjacent flex items do not collapse"; MDN: "Margins don't collapse in a container with display set to flex or grid". These say margins inside a flex or grid container. The container's own vertical margins are those of a block-level box and, by CSS 2.2 §8.3.1 (adjoining siblings), still collapse with an adjacent in-flow sibling.
