## Factual findings

**F-1 · Medium · "only the last request counts" is wrong: the rule is "the highest-ranked waiting request".** §5 "Timers": "A request during the freeze is stored, only the last one counts, and it applies when the freeze ends." Ex 18.4 repeats it: the criterion "several requests during a freeze apply only the last", the test of the same title in `defer-machine.test.ts`, the "Last request" account ("in a placeholder freeze, `trigger`, `loaded`, `trigger` end in Complete, never Loading") and the follow-up "Why does the block skip Loading in the last-request case? Only the last waiting request applies". Evidence: `renderDeferBlockState` in `@angular/core@22.2.1` `_debug_node-chunk.mjs` accepts a request only if `isValidStateChange(currentState, newState) && isValidStateChange(lDetails[NEXT_DEFER_BLOCK_STATE] ?? -1, newState)`, and `isValidStateChange(a, b)` is `a < b`; in the scripted sequence the third call (`trigger`, Loading) is rejected because the stored request (Complete) outranks it, so the *last* request is dropped and the *highest* is applied. The test passes because it asserts Complete, but its title says "the last". Q18.26 states the rule correctly ("A stored request must outrank the one it replaces"; its short answer "higher than the current and the pending one"), so the module contradicts itself. The model in `defer-machine.ts` is right (`pending === null || rank[pending] < rank[next]`); only the words are wrong. Fix: say "the highest-ranked request waiting applies" in §5, the criterion, the test title, the account and the follow-up, keeping the criterion and the test title identical (E2).
