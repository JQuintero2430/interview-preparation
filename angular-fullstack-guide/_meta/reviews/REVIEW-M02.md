## Factual errors

1. **Medium. Line 209 (Coming from the backend, section 3).** Quote: "JavaScript is single-threaded per realm, so a shared captured variable has no visibility or race problems, and there is no need for `final`." Wrong or overbroad: single-threadedness removes memory-visibility issues, but asynchronous code still interleaves at every `await` and callback, so check-then-act on a shared captured variable has logical races (`let busy = false; async function f(){ if (!busy) { await g(); busy = true; } }` lets two calls both pass the check). A backend reader will object. Correction: say "no data races or visibility problems between threads, but interleaving across `await` and callbacks can still produce logical races"; keep "where the analogy breaks" meaning. Evidence: event-loop semantics (Module 04) and the snippet above; reviewer reasoning, not run.
2. **Medium. Q02.08, lines 795 and 802.** Quote: "copy the one number the callback needs instead of capturing the array" and `const contentHeight = rows.length * 24; // capture a number, not 50,000 rows`. Per the spec model this module teaches (lines 174, 664: the closure references the whole environment record), `rows` is still a binding in the same function environment as `contentHeight`, so it stays reachable while the listener is registered. It only drops out because V8 context-allocates just the variables an inner function uses, which Q02.05 line 668 says not to rely on ("Do not rely on either behavior for memory"). The real fix is the `AbortController` (the part that works by spec). Correction: either build the handler in a helper that receives only `panelElement` and `contentHeight` (so `rows` is not in its environment by construction), or say the number-capture is an optimization that engines usually honor but the spec does not guarantee. Evidence: line 668 vs line 802 in the same answer set.
3. **Medium. Lines 454 and 1224 (RxJS recommendation).** Quote: "RxJS provides `debounceTime`, `throttleTime` and `auditTime`" / "prefer the RxJS operators `debounceTime` and `throttleTime` on event streams". The module's own Q02.19 trap and Exercise 02.3 define a throttle as leading **plus trailing**. RxJS `throttleTime` defaults to `{ leading: true, trailing: false }` (`labs/angular/node_modules/rxjs/src/internal/operators/throttleTime.ts` line 51, rxjs 7.8.2), so it drops the last value, which is exactly the trap named at line 1230. Correction: add "pass `{ leading: true, trailing: true }` to keep the last value, or use `auditTime`/`throttleTime` with `trailing`", and say which one is equivalent to Exercise 02.3.
4. **Low. Line 54 (section 1 table).** Quote: "Global environment | the realm (one per page or worker)". A realm exists per global object; an `<iframe>` in the same page has its own realm. Correction: "one per global object (each page, worker or iframe)". Evidence: `node -e 'console.log(require("vm").runInNewContext("globalThis")!==globalThis)'` printed `true` (a second realm in one process); HTML Standard "realm" per global.
5. **Low. Line 102 ("Once true").** Quote: "until ES2015 the only declaration keyword was `var`, which is function-scoped". Slightly too strong: the `catch` parameter was block-scoped since ES3 (ES5 §12.14), and `with` created an object scope. The line-52 table already lists the `catch` clause as a block environment. Correction: "...the only way to declare a variable (other than function declarations and the `catch` parameter) was `var`".
6. **Low. Lines 174 and 664 (spec citation).** "its new function environment gets that stored record as its outer environment ([OrdinaryFunctionCreate])". OrdinaryFunctionCreate only sets `[[Environment]]`; the call-time link is made in PrepareForOrdinaryCall / NewFunctionEnvironment. Correction: cite both (`sec-prepareforordinarycall`) and add the URL to SOURCES.md.
7. **Low. Line 228 vs lines 1067 and 263.** Section 4's problem says "the source of most '`this` is undefined' bugs in Angular callbacks", but Q02.15 (the section's own example) has `this` = `window`, with `this.width` being `undefined`. Correction: "`this` is not the component (often `undefined`, `window`, or the element)". Node check: `setTimeout(function(){'use strict'; console.log(this && this.constructor.name)},0)` printed `Timeout`, so the callback `this` is not even `undefined` in Node (see T-15).
8. **Low. Line 337.** "code passed to `eval` from strict code" is true only for **direct** `eval`. Node check: inside a `"use strict"` function, `(0,eval)("(function(){return this})()") === globalThis` printed `true` (indirect eval is sloppy), while direct `eval` returned `undefined`. Correction: say "direct `eval` called from strict code".
