*Nginx (n; every directive's Default and Context line read):*
- F4. **Matching is on the normalized URI**: "after decoding the text encoded in the “%XX” form, resolving references to relative path components “.” and “..”, and possible compression of two or more adjacent slashes into a single slash."
- F5. **`location` selection** (`ngx_http_core_module`): "nginx first checks locations defined using the prefix strings (prefix locations). Among them, the location with the longest matching prefix is selected and remembered. Then regular expressions are checked, in the order of their appearance in the configuration file. The search of regular expressions terminates on the first match … If no match with a regular expression is found, predicate locations are checked … If no predicate location matches, the configuration of the prefix location remembered earlier is used."; "If the longest matching prefix location has the “^~” modifier, then regular expressions and predicate locations are not checked."; "using the “=” modifier it is possible to define an exact match … If an exact match is found, the search terminates." Predicate locations are new in **1.31.5** (mainline only; §3 names them once and our model does not implement them). **`try_files file ... uri;` / `try_files file ... =code;`**: "Checks the existence of files in the specified order and uses the first found file …"; "$uri/" checks a directory; "If none of the files were found, an internal redirect to the uri specified in the last parameter is made"; the last parameter can be a code ("Starting from version 0.7.51"). `root` default `html`; `alias` "Defines a replacement for the specified location." `etag on;` (default; "appeared in version 1.3.3"); `if_modified_since exact;` (default).
- F6. **Headers** (`ngx_http_headers_module`): `add_header name value [always];` adds the field "provided that the response code equals 200, 201 (1.3.10), 204, 206, 301, 302, 303, 304, 307 (1.1.16, 1.0.13), or 308 (1.13.0)"; "These directives are inherited from the previous configuration level if and only if there are no add_header directives defined on the current level."; "If the always parameter is specified (1.7.5), the header field will be added regardless of the response code." **`add_header_inherit on | merge | off;`** (default `on`; "This directive appeared in version 1.29.3"): "The merge parameter enables appending values from the previous level to the values defined at the current level." **`expires`** (default `off`) sets `Expires` and `Cache-Control` on the same status list; a positive time gives "Cache-Control: max-age=t"; negative gives "no-cache"; `epoch` gives "no-cache"; `max` gives "10 years". So `expires` cannot write `immutable`, and an `add_header Cache-Control …` written next to `expires` produces two headers (C24: the task confirms by reading both directive pages before showing `expires 1y` and `add_header Cache-Control` together; the lab config uses `add_header Cache-Control` only).
- F7. **Compression**: `gzip off;`, `gzip_types text/html;` ("in addition to “text/html”"; "Responses with the “text/html” type are always compressed"), `gzip_comp_level 1;`, `gzip_vary off;`, `gzip_proxied off;`, `gzip_min_length 20;` ("determined only from the “Content-Length” response header field"). `ngx_http_gzip_static_module` "allows sending precompressed files with the “.gz” filename extension instead of regular files" and "is not built by default, it should be enabled with the --with-http_gzip_static_module configuration parameter"; `gzip_static on | off | always;` (default `off`; `always` serves the `.gz` "without checking if the client supports it"). The nginx.org Debian package's configure arguments include `--with-http_gzip_static_module` (`nginx/pkg-oss` `debian/Makefile`; the Alpine package is C11). **Brotli is not in nginx open source** (nginx.org docs: no hit for "brotli"); `google/ngx_brotli` is "a set of two nginx modules" (filter and static, `brotli_static on|off|always`) built with `--add-module` or `--add-dynamic-module`, and `nginx/docker-nginx`'s `modules/README.md` documents building extra modules, listing `brotli`, into the official image with BuildKit.

- F10. **Timeouts and buffering**: `proxy_read_timeout 60s;`: "The timeout is set only between two successive read operations, not for the transmission of the whole response. If the proxied server does not transmit anything within this time, the connection is closed."; `proxy_buffering on;` and "Buffering can also be enabled or disabled by passing “yes” or “no” in the “X-Accel-Buffering” response header field." **WebSocket** (`docs/http/websocket.html`): "since the “Upgrade” is a hop-by-hop header, it is not passed from a client to proxied server", so `proxy_set_header Upgrade $http_upgrade;` and `Connection "upgrade"` (or `map $http_upgrade $connection_upgrade { default upgrade; '' close; }`); the page's example comments `# proxy_http_version 1.1; # before version 1.29.7`; "By default, the connection will be closed if the proxied server does not transmit any data within 60 seconds … can be increased with the proxy_read_timeout directive. ### 1. Where the API calls go: direct calls, a same-origin reverse proxy, an API gateway or a backend-for-frontend · delta 460 (360 + 100 verification paragraph) · SEC-M44-01

### 4. Nginx as the reverse proxy: `proxy_pass`, forwarded headers into Spring Boot, and SSE or WebSocket connections through the proxy · delta 360 · SEC-M44-04
- **Problem:** `/api/orders` reaches Spring as `/orders`, or as `/api/api/orders`; Spring's redirect after login points at `http://` although the user is on HTTPS; the WebSocket upgrade fails with a plain 400 or 404 from Spring; an SSE stream arrives in bursts and is cut after exactly a minute (43:427, 43:1273, 43:2008); someone trusts `X-Forwarded-For` from any client for rate limiting (41:69, M09.md:45).
- **Model:** **`proxy_pass` with a URI** replaces the part of the normalized URI that matched the location with that URI; **without a URI** the request URI is passed as the client sent it (F8; the canonical statement). Nginx **does not pass the client's `Host` and `Connection`**: it sends `Host: $proxy_host` and `Connection: close` unless told otherwise (F9). **Forwarded headers**: the proxy sets `X-Forwarded-Proto`, `X-Forwarded-Host`, `X-Forwarded-For` (or `Forwarded`); Spring Boot uses them only with `server.forward-headers-strategy` `NATIVE` or `FRAMEWORK` (default `NONE` outside a detected cloud platform, F24), and Tomcat trusts them only from `internal-proxies` (private ranges by default, F24); **the edge proxy must drop client-supplied forwarded headers** (F25). **Long-lived connections**: WebSocket needs `Upgrade` and `Connection` set explicitly because they are hop-by-hop (F10), and HTTP/1.1 to the backend (the default only since 1.29.7, F9); SSE needs buffering off (`proxy_buffering off` or the backend's `X-Accel-Buffering: no`) and a heartbeat shorter than `proxy_read_timeout` (60 s between two reads, F10; 43 §3's 15-second comment). Analogy: a receptionist who rewrites the room number on each envelope, and must write "received at the front desk, by courier, from outside" on it, or the department thinks the envelope came from the hallway. Diagram: `sequenceDiagram`: Browser `GET https://app/api/orders` → Nginx (strip or keep prefix; set `X-Forwarded-Proto: https`; drop client's forwarded headers) → Spring (`forward-headers-strategy` → `https` links); a second exchange: `Upgrade: websocket` passed explicitly → `101`; an SSE stream with comments every 15 s under a 60 s read timeout.
