- F6. **Class form, enter** (14382-14447): the classes are added; listeners on `animationstart`/`transitionstart` (outside the zone) add an end listener; in the next `requestAnimationFrame` the runtime measures the longest animation (F8); **if nothing animates, the classes are removed in that frame**; otherwise they are removed when the end event of the longest animation arrives (`enterAnimationEnd`, `event.stopPropagation()` on it). Docs: "Angular removes all classes only after the longest animation has completed."; "Animation classes are only present while the animation is active."
- F7. **Class form, leave** (14474-14557, `animateLeaveClassRunner`): running enter classes are cancelled first (`cancelAnimationsIfRunning`); the leave classes are added; in the next frame the longest animation is measured; **if none, the element is removed in that frame**; otherwise a **fallback `setTimeout` of the longest duration + 50 ms** ends it if no end event arrives (`animation-fallback`), and the end event of the longest animation (or a cancel event, F11) removes the classes and resolves the removal. **No provider is needed**: nothing in this path reads `ANIMATION_MODULE_TYPE` or a renderer from `@angular/animations`.
- F8. **Longest-animation detection** (3958-4068): `determineLongestAnimation` uses `el.getAnimations()`; if the list is empty it falls back to `getComputedStyle` (`animation-name`/`-duration`/`-delay`/`-iteration-count` and `transition-property`/`-duration`/`-delay`); duration = delay + duration, divided by `playbackRate`; **an animation with `iterations: Infinity` (or `animation-iteration-count: infinite`) is skipped**, so an infinite animation never delays removal; `isLongestAnimation` (4238-4256) accepts an end event only from the element itself, matching the longest animation's name or transitioned property (`all` matches any), with a 1 ms tolerance.
- F9. **The queue** (4494-4560): `ANIMATION_QUEUE` is a per-`EnvironmentInjector` token holding a `Set` of animation functions; `scheduleAnimationQueue` runs the whole set **in one `afterNextRender` callback** after the next render, then clears it. Enter animations are queued when their node is inserted (`maybeQueueEnterAnimation`, 4567, 4598-4600); leave animations are queued by `runLeaveAnimationsWithCallbackImpl` (4601-4620), and the DOM removal (`nativeRemoveNode`) waits for the callback (`applyToElementOrContainer` 4825-4870).
- F10. **v22 leave semantics** (4621-4760; d): when a node is removed, `aggregateDescendantAnimations` collects leave animations of that node **and of its descendants in the same view**, and `collectNestedViewAnimations` adds those of **embedded views** (`TView` type 2, the views of `@if`, `@for`, `@switch` and `ng-template`) inside containers under it; it does **not** enter child component views, so a child component's own `animate.leave` does not run before the parent's removal. All promises are awaited with `Promise.allSettled` before removal (4643-4680). CHANGELOG 22.0.0 Breaking Changes: "Leave animations are no longer limited to the element being removed." Commit df659b8d0c ("re-introduce nested leave animations scoped to component boundaries"): "Wait for nested inner `animate.leave` transitions natively only when they exist within the same component's view or its embedded tracking structures (like `@if` and `@for`)." History: 21.2.0 "add support for nested animations" (ea2016a6dc); 21.2.4 "reverts 'feat(core): add support for nested animations'" (abbd8797bb); 22.0.0 re-introduced with the component boundary. Docs `enter-and-leave.md` § "Element removal order": "Child animations fire only for elements within the same component template." Also 22.0.0: "change AnimationCallbackEvent.animationComplete signature" — commit b9b5c279b4 changed `animationComplete: Function` to `VoidFunction` (types only).
- F11. **Re-insertion during a leave** (4133-4190, 4838-4868): a node that is leaving is tracked per template node (`leavingNodes`); when the same template node inserts an element again, `cancelLeavingNodes` dispatches a synthetic `animationend` with `detail.cancel` on the leaving element and removes it (or re-uses it when it is the very same element, `reusedNodes`), so a quick remove-then-add does not leave two copies. CHANGELOG 20.3.7 "prevent duplicate nodes from being retained with fast `animate.leave` calls"; 20.2.0 "prevents duplicate nodes when `@if` toggles with leave animations"; 20.3.1 "Prevent leave animations on a move operation"; 20.3.11 "skip leave animations on view swaps"; 22.2.0 "cancel leave animations in nested views during list reordering".
- F12. **Values a binding may take** (r, d): a string with space-separated classes, an array of class strings, or (22.2.0 "support function and signal bindings in animate.enter and animate.leave", de5889ec4f) a function or signal returning one (`getClassListFromValue` 4200-4210 unwraps functions repeatedly). Syntaxes: `animate.enter="cls"`, `[animate.enter]="expr"`, `(animate.enter)="fn($event)"` and the same for leave (compiler `ANIMATE_PREFIX = 'animate.'`, `compiler.mjs` 23508; event parsing 30985-30996; ops 10405-10413).

### 1. Motion in a UI: what to animate, the browser's three animation mechanisms and where Angular fits · delta 850 (750 + 100 verification paragraph) · SEC-M35-01 (Opus)
- **Problem:** a list item vanishes the instant it is deleted and users cannot tell which row went; a modal pops in with no cue where it came from; a team adds `@angular/animations` to fade one button and ships an animation engine for it (F14, F15).
- **Model:** motion answers "what changed and where did it go". The browser has three mechanisms: a **CSS transition** (animates a property from its old to its new computed value when the value changes), a **CSS keyframe animation** (runs a named `@keyframes` sequence when the `animation` property applies) and the **Web Animations API** (script creates `Animation` objects); all three produce `Animation` objects on the document timeline (`getAnimations()`). Angular's current API adds only **timing around insertion and removal**: `animate.enter` adds classes when an element is inserted and removes them when the animation ends; `animate.leave` adds classes and **delays the DOM removal** until it ends (F6, F7); the router can wrap navigations in a view transition (F20). Analogy: the browser is the orchestra; Angular is the stage manager who says when an actor walks on and holds the curtain until the bow ends. Diagram: `flowchart LR`: `"state change"` → `"CSS transition"`, `"CSS @keyframes"`, `"element.animate()"`; all three → `"Animation objects (document timeline)"` → `"style, layout, paint, composite"`; separate `"animate.enter / animate.leave"` → `"adds classes / delays removal"` → `"CSS transition"` and `"CSS @keyframes"`; `"withViewTransitions"` → `"document.startViewTransition"`. **What to notice:** Angular feeds the browser's mechanisms; it does not run its own.
- **Mechanism:** **read from the `@angular/core` 22.2.1 source** (`_debug_node-chunk.mjs`, internal `areAnimationSupported`, F4): the native path needs `getAnimations` and is off on the server and under jsdom, which is why the module's on-screen tests run in Chromium; no provider is involved (F2, F7). One paragraph on when to animate: feedback, continuity of position, attention; when not to (decoration that delays work), with the reduced-motion forward link (§11).
- **First-use definitions:** animation, transition, keyframe, timeline, `Animation` object, compositor (link 08 §2), enter animation, leave animation, provider (link 16 §7).
- **Verification:** `labs/e2e/tests/35-animations/concepts/section-1-mechanisms.spec.ts` (page `/m35/mechanisms`: three boxes, one per mechanism, triggered by buttons): `Section 1: each mechanism creates an Animation object on the element` (asserts `kind` is `css-transition`, `css-animation` and `script` from `animationsOf`), `Section 1: the native build has no animation provider and still runs animate.enter` (reads `ANIMATION_MODULE_TYPE` through a page-exposed `inject(ANIMATION_MODULE_TYPE, { optional: true })` = `null`, probe first, and sees the enter class on the home page's paragraph); `labs/angular/src/app/modules/35-animations/concepts/section-1-jsdom.spec.ts` (`ng test`): `Section 1: under jsdom animate.enter adds no class even with animationsEnabled` (probe first, F4, F13).
- **Questions drilled:** Q35.01.
- **Misconceptions:** "Angular animations need `@angular/animations`" (cause: every pre-v20.2 tutorial imported it; F7 and the provider-free test); "`animate.enter` is a directive you import" (cause: it looks like an attribute directive; the docs say the compiler handles it, F18); "if a test passes with `animate.leave`, the animation works" (cause: tests pass because jsdom and `TestBed` switch the path off, F4, F13, tested); "more motion makes an app feel faster" (cause: motion is noticed; it adds time unless it overlaps work, links §11).
- **The verification paragraph** (placeholder before §1, 80-110 words): Playwright 1.63.0 on Chromium 153 against the production builds of the `animations-lab` project (the native build and, unless declined, the `legacy` build under `/legacy/`), served on port 4700, with `reducedMotion` set in every context; `ng test` (jsdom, development mode) for what has no screen: tokens, `TestBed` options, compile-time types, legacy callbacks under the noop driver, `NG05105`; source reads of `@angular/core`, `compiler`, `platform-browser`, `router` 22.2.1 and `@angular/animations` 22.2.1; docs and MDN on the stated dates; documented only: other browsers.

### 2. CSS transitions: triggers, interruption, events and entry with `@starting-style` · delta 700 · SEC-M35-02
- **Problem:** a dropdown toggled with `display: none` never fades; a hover transition snaps back when the pointer leaves halfway; a freshly inserted toast appears at full opacity because there was no "before" value.
- **Model:** a transition watches a property; when its computed value changes it animates from the current value to the new one over `transition-duration` after `transition-delay` with an easing. A change mid-flight **reverses from where it is** (reversing shortening). An inserted element has no previous style, so nothing transitions unless **`@starting-style`** supplies the "before" values [Baseline 2024: newly available, per MDN]; discrete properties like `display` and `overlay` need `transition-behavior: allow-discrete` (limited availability, C5). Analogy: a dimmer switch: it only moves when you turn it, and from where it is now. Diagram: `stateDiagram-v2`: `idle` → `pending: value changes` → `running: transitionrun / delay ends → transitionstart` → `idle: transitionend`; `running` → `idle: transitioncancel (value removed or display none)`. **What to notice:** `transitionrun` fires before the delay, `transitionstart` after it.
- **Mechanism:** the four transition events and their order (probe first, C4); `transition-property: all` versus a list; transitions on properties that change layout versus compositor-only ones (link 08 §2 once); why `getAnimations()` returns a `CSSTransition` with `transitionProperty`; **read from the `@angular/core` 22.2.1 source** (F8) that Angular's enter and leave timing reads exactly these values (`transition-property`, `-duration`, `-delay`), so the CSS you write is the timing Angular waits for. Link 10 §5 once for media-query syntax.
- **First-use definitions:** transition, easing (timing function), delay, reversing, `@starting-style`, discrete property, `transition-behavior`, `CSSTransition`.
- **Verification:** `labs/e2e/tests/35-animations/concepts/section-2-transitions.spec.ts` (page `/m35/transitions`): `Section 2: a class change starts a CSSTransition for each listed property`, `Section 2: transition events fire in the order the run shows` (probe first; asserts `recordEvents` order), `Section 2: removing the class mid-flight cancels or reverses the transition as the run shows` (probe first, `seek`), `Section 2: an inserted element transitions only with @starting-style`, `Section 2: display none animates out only with transition-behavior allow-discrete` (probe first).
- **Questions drilled:** Q35.02, Q35.03, Q35.04.
- **Misconceptions:** "`transition: all` is harmless" (cause: it is short; it animates every changing property, including layout ones, and Angular's longest-animation measure then waits for the slowest, F8); "a transition can animate an element in on insertion" (cause: it works on toggled classes; insertion has no "from" value without `@starting-style`, tested); "`display: none` can never be animated" (cause: true before `allow-discrete`; now possible where supported, C5, tested in Chromium only).

### 3. CSS keyframe animations: `@keyframes`, fill modes, iteration and component-scoped names · delta 600 · SEC-M35-03
- **Problem:** a spinner defined in a component works there but a global `.spin` class elsewhere finds no animation; a pulse that should end visible snaps back to its start style; an infinite animation on a leaving element seems to block removal (it does not, F8).
- **Model:** `@keyframes name { from {…} to {…} }` declares a sequence; the `animation` shorthand applies it with duration, delay, easing, `iteration-count`, `direction`, `fill-mode` and `play-state`. Fill mode decides what applies before and after the active interval. Analogy: a flip-book you can play once, loop, or freeze on the last page. Diagram: `flowchart LR`: `"before (delay)"` → `"active (iterations)"` → `"after"`; notes `"fill-mode backwards applies first keyframe"` on before, `"fill-mode forwards keeps last keyframe"` on after. **What to notice:** without `forwards`, the end state comes from the normal cascade, not from the keyframes.
- **Mechanism:** `animationstart`, `animationiteration`, `animationend`, `animationcancel`; `CSSAnimation.animationName`; **read from the `@angular/compiler` 22.2.1 source** (`_scopeKeyframesRelatedCss`, F19) why a component's `@keyframes` is renamed and where that stops (13 §9 owns the rule; one paragraph, link once); **read from the `@angular/core` 22.2.1 source** that an infinite animation is ignored when Angular decides how long to wait (F8).
- **First-use definitions:** `@keyframes`, fill mode, iteration count, direction, play state, `CSSAnimation`, emulated encapsulation (link 13 §9).
- **Verification:** `labs/e2e/tests/35-animations/concepts/section-3-keyframes.spec.ts` (page `/m35/keyframes`): `Section 3: an animation with fill-mode forwards keeps its last keyframe after finishing`, `Section 3: without forwards the element returns to its own style`, `Section 3: animationiteration fires once per completed iteration` (probe first; `seek` across two iterations), `Section 3: a global class cannot use a component's keyframes` (asserts the scoped name in the page's stylesheet and no `CSSAnimation` on the global-class element).
- **Questions drilled:** Q35.03, Q35.04.
- **Misconceptions:** "an animation's last keyframe stays by default" (cause: it looks that way with matching base styles; it reverts without `forwards`, tested); "keyframe names are global in Angular" (cause: they are global in plain CSS; emulated encapsulation renames local ones, F19, tested); "`animation-iteration-count: infinite` on a leaving element keeps it forever" (cause: reasonable guess; Angular skips infinite animations when measuring, F8, tested in §5).

### 4. The Web Animations API: `element.animate`, the `Animation` object and `getAnimations` · delta 650 · SEC-M35-04
- **Problem:** a drag-to-dismiss card needs an animation whose end value is computed from the pointer, a "pause all" button for a dashboard, and code that waits for an animation to finish before focusing the next field; CSS alone can do none of these.
- **Model:** `element.animate(keyframes, options)` [Baseline 2022: widely available, per MDN] returns an **`Animation`** that owns a **`KeyframeEffect`** (the keyframes and timing) and runs on a **timeline** (the document timeline by default); it can `play`, `pause`, `reverse`, `finish`, `cancel`, change `playbackRate` and `currentTime`, and exposes `finished` and `ready` promises. CSS transitions and animations are the same objects (`CSSTransition`, `CSSAnimation`), so `getAnimations()` [Baseline 2023: widely available, per MDN] lists all of them. `commitStyles()` writes the current animated values into the inline style. Analogy: CSS animations are a playlist the browser runs; WAAPI hands you the remote. Diagram: `classDiagram`: `Element` "1" --> "*" `Animation` : getAnimations(); `Animation` --> `KeyframeEffect` : effect; `Animation` --> `AnimationTimeline` : timeline; `Animation` : playState, currentTime, playbackRate, finished, play(), pause(), reverse(), finish(), cancel(), commitStyles(); `CSSAnimation` --|> `Animation`; `CSSTransition` --|> `Animation`. **What to notice:** one object model under all three mechanisms.
- **Mechanism:** `finished` resolves on finish and rejects with an `AbortError` on `cancel()` (probe first); `fill: 'forwards'` keeps effects alive and why `commitStyles()` then `cancel()` is the documented way to keep the end style without a lingering effect; **read from the `@angular/core` 22.2.1 source** (`determineLongestAnimationFromElementAnimations`, F8) that Angular reads `effect.getTiming()` and `playbackRate`, so a WAAPI animation started in an `animate.leave` callback is measured the same way; **read from the `@angular/animations` 22.2.1 tarball** (`WebAnimationsPlayer`, F15) that the legacy package itself ends in `element.animate`.
- **Callout (required):** *Framework vs platform*: the browser provides transitions, keyframes, WAAPI, `getAnimations` and the events; Angular's current API decides only **when classes are added and removed and when a node leaves the DOM** (F6-F9); the legacy package was an engine that computed keyframes and played them through WAAPI (F15).
- **First-use definitions:** Web Animations API, `KeyframeEffect`, timeline, `playState`, `finished` promise, `commitStyles`, `playbackRate`.
- **Verification:** `labs/e2e/tests/35-animations/concepts/section-4-waapi.spec.ts` (page `/m35/waapi`): `Section 4: element.animate returns an Animation that getAnimations lists with CSS ones`, `Section 4: finished resolves after finish and rejects after cancel` (probe first), `Section 4: commitStyles then cancel keeps the end style without an animation`, `Section 4: pausing every animation from getAnimations freezes the page's motion`.
- **Questions drilled:** Q35.05.
- **Misconceptions:** "WAAPI is a polyfill-era API you should avoid" (cause: it needed a polyfill years ago; it is widely available, F22); "`getAnimations()` only returns script animations" (cause: the name; it returns CSS ones too, tested); "`fill: 'forwards'` is the way to keep an end state" (cause: it works visually; the effect stays active and overrides later style changes, so commit then cancel, tested).

### 5. `animate.enter` and `animate.leave` with CSS classes: syntax, bindings and when the element leaves · delta 750 · SEC-M35-05
- **Problem:** an `@if` panel should fade in and slide out; before v20.2 that meant `@angular/animations` and a trigger; with plain CSS the leave never shows because the element is gone before the animation could run.
- **Model:** `animate.enter="cls"` [Stable since v20.2] adds the classes when the element is inserted and removes them when its **longest** animation ends; `animate.leave="cls"` adds the classes when the element is about to be removed and **removes the element when its longest animation ends** (F6-F8). Values: one or more space-separated classes, an array, a bound expression `[animate.enter]="expr"`, or [Changed in v22.2: a function or signal may be bound] (F12). Works on elements and as a **host binding** (`host: { 'animate.enter': 'm35-in' }`, F18; link 13 §7 once). With transitions, the enter class is the **target** state, so pair it with `@starting-style` (F18; link §2). Analogy: a theatre's entrance and exit cues. Diagram: `sequenceDiagram`: `participant T as Template`, `R as Runtime`, `E as Element`, `B as Browser`: `T->>R: @if becomes true`, `R->>E: insert, add enter classes`, `R->>B: next frame: measure longest (getAnimations)`, `B-->>R: animationend (longest)`, `R->>E: remove enter classes`; then `T->>R: @if becomes false`, `R->>E: add leave classes`, `B-->>R: animationend (longest)`, `R->>E: remove from DOM`. **What to notice:** removal waits on the browser's event, with a fallback timer (§12).
- **Mechanism:** **read from the `@angular/core` 22.2.1 source** (`animateLeaveClassRunner`, F7) the three outcomes: nothing animates → removed in the next frame; something animates → removed at the longest one's end; no end event → fallback timer (longest + 50 ms, read, not run); running enter classes are cancelled when a leave starts; an infinite animation does not count (F8). The longest-animation rule means short and long effects on one element keep the classes until the long one ends (Q35.06).
- **First-use definitions:** enter classes, leave classes, longest animation, host binding (link 13 §7), signal (link 17).
- **Verification:** `labs/e2e/tests/35-animations/concepts/section-5-enter-leave-classes.spec.ts` (page `/m35/enter-leave`): `Section 5: the enter class is present while the animation runs and removed after it`, `Section 5: the element stays in the DOM until its leave animation ends`, `Section 5: a leave class that animates nothing removes the element at once` (asserts removal without `finishAll`), `Section 5: an infinite animation does not delay removal` (F8), `Section 5: an array and a signal-bound class list both apply` (F12), `Section 5: animate.enter works as a host binding` (probe first, F18).
- **Questions drilled:** Q35.06, Q35.07, Q35.08.
- **Misconceptions:** "the leave class must undo the enter class" (cause: legacy `:leave` mirrored `:enter`; any animation that runs is waited for, tested); "classes stay on the element after the enter animation" (cause: legacy states kept styles; the runtime removes them at the end, F6, tested); "`animate.leave` keeps an element forever if the animation never ends" (cause: reasonable fear; infinite animations are skipped and a fallback timer exists, F7, F8).

History as "Once true": until v21.1 only the removed element animated; 21.2.0 added nested animations and 21.2.4 reverted it; 22.0.0 brought them back scoped to component boundaries (F10). ### 7. Animating lists: `@for` enter, leave, reorder and stagger · delta 700 · SEC-M35-07
- **Problem:** a notifications list where new items pop, deleted ones vanish, sorting makes everything flash because rows are re-created, and quickly undoing a delete shows the row twice.
- **Model:** with a stable `track` (link 18 §2), `@for` **inserts**, **removes** or **moves** rows (Q18.25); `animate.enter` runs on inserted rows, `animate.leave` on removed rows, and **moves run neither** (F11, CHANGELOG 20.3.1). A row removed and re-added before its leave ends is not duplicated: the leaving copy is cancelled (F11). Stagger: a per-row delay from `$index` through a CSS custom property (`[style.--i]="$index"` and `animation-delay: calc(var(--i) * 40ms)`), the docs' replacement for `stagger()` (F17). Analogy: a queue at a counter: newcomers walk in, leavers walk out, people who just shuffle places do not leave and come back. Diagram: `flowchart TB`: `"new list"` → `"@for diff (track)"` → `"insert"` → `"animate.enter"`; → `"remove"` → `"animate.leave, removal delayed"`; → `"move"` → `"no enter, no leave"`; `"re-add during leave"` → `"leaving copy cancelled"`. **What to notice:** only identity decides which animation runs, so `track $index` turns moves into leaves and enters.
- **Mechanism:** **read from the `@angular/core` 22.2.1 source** (`cancelLeavingNodes`, `trackLeavingNodes`, `applyToElementOrContainer`, F11) how a re-insert cancels a pending leave with a synthetic `animationend` carrying `detail.cancel`; why `track $index` changes which animation runs (link Q18.07 once); a FLIP-style glide for moves via WAAPI as an option, labelled as a pattern the lab implements, not an Angular feature.
- **First-use definitions:** reorder (move), stagger, FLIP (first, last, invert, play), custom property (link 10).
- **Verification:** `labs/e2e/tests/35-animations/concepts/section-7-lists.spec.ts` (page `/m35/lists`): `Section 7: an added row runs its enter animation and a removed row its leave animation`, `Section 7: reordering with track item.id runs no enter or leave animation`, `Section 7: reordering with track $index runs enter and leave animations` (probe first), `Section 7: re-adding a row during its leave animation leaves one copy` (F11), `Section 7: each row's animation-delay follows its index` (asserts `getTiming().delay` values, C11).
- **Questions drilled:** Q35.12, Q35.13.
- **Misconceptions:** "`@for` re-renders the list, so every row animates on sort" (cause: older `*ngFor` with no `trackBy` did re-create rows; with a stable `track` moves keep the nodes, tested); "you need `stagger()` from `@angular/animations` for cascades" (cause: legacy tutorials; a custom property and `animation-delay` do it, F17, tested); "re-adding during a leave shows two rows" (cause: it did in early 20.x, CHANGELOG 20.2.0 and 20.3.7; fixed, tested).

### 11. Performance and reduced motion: compositor properties, measuring jank and `prefers-reduced-motion` · delta 700 · SEC-M35-11

### 12. Under the hood: from `animate.leave` to a removed node · delta 650 · SEC-M35-12 (Opus)
