### 1. Library, framework, progressive framework: what each project decides for you · delta 800 (700 + 100 verification paragraph) · SEC-M40-01
- **Problem:** an interviewer asks "Angular is a framework and React is a library: what does that mean in practice?" and most answers are slogans; a team that picks React expecting a router, forms and a test runner in the box, or picks Angular expecting to swap its rendering engine, pays for the wrong assumption for years.
- **Model:** a spectrum by **what is decided for you**: a **UI library** renders components you call into a root and leaves routing, data, forms, build and tests to you (React describes itself as "a JavaScript library for building user interfaces", F3; react.dev recommends "starting with a framework" such as Next.js or React Router, F7); a **progressive framework** starts as a library you can drop into a page and adds official pieces as you need them (Vue: "a framework that can grow with you", official router, Pinia, Vite, F11); a **full framework** owns the entry point, compiler, DI, router, forms, HTTP, CLI and test builder as one release group (Angular, link 12 §1 once for inversion of control and the package group, F16, F17); a **compiler-first** design moves work to build time (Svelte, F11's "reactivity during compilation"; Solid compiles JSX to DOM operations, F12). Analogy: a kitchen: a knife set (library), a modular kitchen you extend cabinet by cabinet (progressive), a fitted kitchen delivered and serviced by one maker (framework). Diagram: `flowchart LR`: a spectrum "you decide" → "it decides": React (+ meta-framework), Preact, Solid, Vue, Svelte (+ SvelteKit), Angular, with one label each.
- **Mechanism:** **read from each package** (F3, F5, F9, F12) to answer "why do people call React a library and Vue a framework?": `react` 19.3.1 has no dependencies and exports components, hooks and context only (F5), routing and data live in other packages (F18); `vue` 3.5.44 bundles its compiler, runtime and server renderer as dependencies of one package (F9); Angular's packages move together through `ng-update.packageGroup` (owner 12 §1). Meta-frameworks (Next.js, Nuxt, SvelteKit) are the frameworks built on libraries (F1, F7): the boundary moved, it did not vanish.

### 2. Templates, JSX and single-file components: what the compiler knows · delta 650 · SEC-M40-02
- **Problem:** "templates or JSX?" turns into taste; the real difference is what each format lets a compiler see: a React team ships a list where every render allocates new callbacks and objects, an Angular team fights a template that cannot express a loop it needs, and neither can say why.
- **Model:** a **template** is a restricted language the compiler parses ahead of time, so it knows which nodes are static and which bindings can change (Angular: link 12 §8 once; Vue: "templates are compiled into render functions" with patch flags marking dynamic parts, F10, F11); **JSX** is JavaScript syntax for `createElement` calls (React), so the render function is ordinary code that the runtime re-runs and whose output it compares (F6, F7); **Solid's JSX** compiles to real DOM creation plus one effect per dynamic expression (F12); a **single-file component** (`.vue`, `.svelte`) puts template, script and style in one file the compiler splits. Analogy: a printed form with blanks (template: the printer knows which boxes change) versus a letter written fresh each time (JSX: anything goes, so the post office compares letters). Diagram: `flowchart TD` four lanes from source to update: Angular template → compiled instructions → binding slots (12 §8); Vue template → render function + patch flags → patch dynamic nodes; React JSX → `createElement` tree → re-render + diff; Solid JSX → DOM + per-expression effects.
- **Mechanism:** **read from `@vue/compiler-core` and `@vue/shared` 3.5.44** (F10) to answer "how can a virtual DOM skip static nodes?": patch flags such as `TEXT` 1 and `CLASS` 2 and `dynamicChildren` tell `patch` which nodes to compare, the "compiler-informed virtual DOM" (F11); what JSX gives back: the full language for conditional and repeated structure, and types through TypeScript's JSX checking; what templates give back: static analysis, template type checking in Angular (link 12 §7 once) and patch hints in Vue. React's compiler (§3) adds analysis to JSX without changing its semantics (F7).
- **First-use definitions:** template, JSX, render function, single-file component (SFC), patch flag, static hoisting (only if the task reads it in `@vue/compiler-core`; else omitted).
- **Verification:** documented only (F10-F12, 12 §8 owner); no lab test.
- **Questions drilled:** Q40.02.
- **Misconceptions:** "JSX is HTML in JavaScript" (cause: it looks like markup; it compiles to function calls, and attributes are props, F5's `createElement`); "templates are less powerful, so they are slower" (cause: fewer constructs; the restriction is what lets Angular's and Vue's compilers mark static parts, F10, 12 §8); "Solid is React with signals" (cause: both use JSX; Solid's components run once and its JSX compiles to DOM operations, F12).

### 3. React's model: re-rendering, reconciliation, memoization and the React Compiler · delta 850 · SEC-M40-03 (Opus)
- **Problem:** a React developer joins an Angular team (or the reverse) and asks why a parent's state change re-runs every child, why an inline `style={{…}}` defeats `memo`, why a list keyed by index loses input focus, and whether the React Compiler makes React "like signals"; an Angular interviewer asks the candidate to explain React's model precisely to compare it with Angular's.
- **Model:** in React, **state lives in components**; `setState` schedules a **re-render**: React calls the component function again and, by default, every child it returns (F6, F7 quote); the new element tree is **reconciled** against the old one (same type and key: keep the DOM node and update props; otherwise replace), and only the differences are **committed** to the DOM. **Bailouts** cut work: an `Object.is`-equal `setState` schedules nothing (F6, F7 16.8.0), `memo` skips a child whose props are shallow-equal by `Object.is` (F6), and a changed context reaches readers even below a skipped `memo` (F6). The **React Compiler** (1.0, 2025-10-07, F2, F7, F8) inserts that memoization at build time through a per-component memo cache (`useMemoCache`, F5); the model stays re-render based. Analogy: a newspaper that reprints the whole page on any correction (re-render), with a proofreader who only replaces the lines that differ (reconciliation); `memo` is a "no changes in this column" stamp. Diagram: `flowchart TD`: `setState` → `Object.is` equal? → yes: nothing / no: schedule → render component → for each child: `memo` and props shallow-equal and no context change? → skip / else render → reconcile by type and key → commit DOM changes.
- **Mechanism:** **read from `react-dom` 19.3.1** (F6, internal names marked, C11) to answer "why does a child without `memo` re-render when its props did not change?": `beginWork` compares the props **object** by identity, and a parent's render always creates a new one; `memo`'s `shallowEqual` compares each prop with `Object.is`, so a new inline object or function defeats it; `dispatchSetStateInternal`'s eager `Object.is` bailout; keys: `placeChild` and `lastPlacedIndex` decide moves, and the two key warnings (F6). The compiler: options and directives (F8), what it does not change (rules of React, re-render semantics; F7 quote). Contrast once with Angular: a signal read marks one view (link Q21.34, 21 §1's test), not a subtree; the compiled template compares bindings, not trees (link Q12.27 once; never re-asked, C14).
- **First-use definitions:** component state, re-render, reconciliation, commit, key, `memo`, shallow equality, bailout, context (React), React Compiler, memo cache.
- **Verification:** `labs/ts-js/src/modules/40-framework-comparisons/concepts/mini-rerender.ts` (≈60 lines: components as functions of props, `useState` with an `Object.is` eager bailout, `memo` with a shallow `Object.is` compare, a context value read by consumers; a render log; **stated as our model of React 19.3.1's bailout rules, C8**) and `concepts/section-3-rerender.test.ts`: `Section 3: our model re-runs a child without memo whenever its parent re-renders`; `Section 3: our model skips a memo child whose props are shallow-equal`; `Section 3: our model re-renders a memo child that receives a new inline object`; `Section 3: our model schedules nothing for a setState with an Object.is-equal value`; `Section 3: our model re-renders a context reader below a skipped memo parent`.
- **Questions drilled:** Q40.03, Q40.04, Q40.05. Practised in Exercise 40.1.
- **Misconceptions:** "React re-renders the whole DOM on every change" (cause: "re-render" sounds like repaint; React re-runs component functions and commits only the differences, F6, F7); "`memo` makes a component update only when its props change" (cause: the name; a changed context or the component's own state still renders it, and a new object prop defeats it, F6); "the React Compiler turns React into signals" (cause: the docs call the result "fine-grained reactivity" (F7 quote); components still re-run when their inputs change, and the compiler only skips work it can prove unchanged, F7, F8); "keys are for performance only" (cause: the warning appears in lists; a key is identity, and a changed key discards the child's state, F6 warning text).

### 4. Signals beyond Angular: Vue refs, Solid, Svelte runes, Preact and Qwik · delta 800 · SEC-M40-04 (Opus)
- **Problem:** "Angular adopted signals, so it works like Solid now", "Vue has had signals for years", "Svelte 5 copied React": interviewers test whether the candidate knows what "signals" means in each system, where updates land (a component, a view, a DOM node) and which habits break when moving between them.
- **Model:** a **signal** is a value container that records who reads it and notifies them on write (link 17 §1 once; Vue's docs: "the same kind of reactivity primitive as Vue refs", F11). The systems differ on five axes: **read/write API** (Angular `count()` / `set`; Vue `ref.value`; Solid `[get, set]` from `createSignal`; Svelte `$state` variables compiled to `source`/`set` calls, C2; Preact `.value`, F14); **equality** (Angular `Object.is` by default, owner 17; Vue `hasChanged` = `!Object.is`, F9; Solid `===`, F12); **deep reactivity** (Vue `ref` of an object is a Proxy, F9, link Q03.14 once; Svelte `$state` proxies objects only after the C2 read; Angular and Solid signals are shallow); **granularity** (where a write lands: a Vue component's render effect, F10; an Angular view, link Q21.34; a Solid DOM expression, F12; a Svelte template effect, F13); **scheduling** (Vue microtask queue, F10; Solid synchronous `runUpdates`, F12; Angular's scheduler, link 21 §5 once). Qwik's signals serve **resumability** (F17; C5). Analogy: the same thermostat sold by five makers: all report temperature changes, but one rings the whole house, one each room, one each radiator. Diagram: `flowchart LR`: a write → Angular: mark view dirty → refresh view bindings; Vue: trigger component effect → re-render component → patch; Solid: run the bound DOM effect; Svelte: run the template effect; React (contrast): schedule component re-render.
- **Mechanism:** **read from the shipped sources** (F9, F10, F12, F13, F14; internal names marked, C11) to answer "why does a Solid component body run only once while a Vue component re-renders?": Solid's `createComponent` runs the body inside `untrack`, and `solid-js/web`'s `insert` puts each dynamic expression in its own render effect (F12); Vue tracks reads made during the whole component render inside one `ReactiveEffect` (F10); Vue's computed refresh uses version numbers (`globalVersion`, `isDirty`, F9), close to Angular's version-based pull (link 17 §9 and Q17.33 once). The `Framework vs platform` callout: none of these is a JavaScript feature; the TC39 proposal is at Stage 1 (F15, link Q17.38 once, never re-asked). One sentence from M22's pointer: RxJS is not part of React or Vue (F5, F9), and Angular's interop is 17 §8.
- **First-use definitions:** signal (link 17 §1), ref (Vue), `reactive` Proxy (link 03 §5), rune (Svelte), render effect, granularity, resumability (Qwik), fine-grained reactivity (link 21 §1).
- **Verification:** `labs/ts-js/…/concepts/mini-fine-grained.ts` (≈50 lines, jsdom: `createSignal` with `===` equality, an effect list, a component function called once inside an untracked scope, and an `insertText(node, () => value)` helper that creates one effect per bound text node; **stated as our model of Solid 1.9.17's update path, C8**) and `concepts/section-4-fine-grained.test.ts` (`// @vitest-environment jsdom`): `Section 4: our fine-grained model calls the component function once`; `Section 4: our fine-grained model writes only the text node bound to the changed signal`; `Section 4: a value read into a constant in the component body never updates in our fine-grained model`.
- **Questions drilled:** Q40.06, Q40.07.
- **Misconceptions:** "signals are a new idea Angular introduced" (cause: Angular's v16 launch; Vue's docs trace the idea to Knockout observables and Meteor Tracker, F11; link 17 §1's misconception once); "all signal frameworks update the same unit" (cause: one word for several designs; Vue re-renders a component, Angular refreshes a view, Solid runs one DOM effect, F10, F12, Q21.34); "a Vue `ref` and an Angular signal behave the same with objects" (cause: both wrap a value; a Vue `ref` makes an object deeply reactive through a Proxy, an Angular signal notifies only on a new reference, F9, owner 17); "Svelte 5 runes are React hooks" (cause: both appeared as "the new way" in a major; runes compile to signal reads and writes, not to per-render hook calls, F13, C2).

### 5. Dependency injection and shared state: injectors, context and provide/inject · delta 650 · SEC-M40-05
- **Problem:** "React doesn't have DI, so how do you test or swap services?" and "isn't Vue's provide/inject the same as Angular's DI?" are common; a team that ports a React app with context-based services into Angular (or the reverse) often recreates the wrong scope and either leaks state across routes or re-creates services on every render.
- **Model:** three ways to hand a dependency down a tree: **Angular's injector hierarchy** resolves typed tokens through element, environment and platform injectors and constructs services itself, with scopes and tree-shaking (link 16 §1 and §5 once; Q16.35 owns the Spring comparison); **React context** passes a **value** (not a constructor) from the nearest provider above, and every reader re-renders when that value changes by `Object.is` (F5, F6); **Vue `provide`/`inject`** looks a key up through a prototype chain of the ancestors' `provides` objects, only during `setup` (F10); Solid's `useContext` walks the owner tree (F12), Svelte has `setContext`/`getContext` (F13). Analogy: a company directory that also hires the person you ask for (Angular), versus a note passed down the org chart that says who to call (context). Diagram: `flowchart TD`: component asks for X → Angular: element injector → parent injectors → environment injector → create or reuse instance; React: nearest `<Context>` above → value; Vue: own `provides` → prototype chain of ancestors' `provides` → app `provides`.
- **Mechanism:** **read from `react` 19.3.1 and `@vue/runtime-core` 3.5.44** (F5, F6, F10) to answer "why does a React context with an object literal value re-render every reader?": the provider's value is compared with `Object.is`, so a new object each render notifies all readers (F6 `propagateContextChanges`); Vue's `inject` returns whatever was provided, reactive only if a `ref` or `reactive` was provided (F9, F10); React 19's `<Context>` renders as its own provider (F5). Testing: Angular overrides providers in `TestBed` (link 29 once); React and Vue tests wrap the component in a provider or pass `global.provide` (the task reads Vue Test Utils' `mount` options before stating it, else omits).
- **First-use definitions:** dependency injection (link 16 §1), injector, token, context (React), provider (React sense), `provide`/`inject` (Vue), owner tree (Solid).
- **Verification:** documented only (F5, F6, F10, F12, F13, owner 16).
- **Questions drilled:** Q40.08.
- **Misconceptions:** "React context is dependency injection" (cause: both hand a dependency down; context passes a value and never constructs, scopes or tree-shakes services, F5, link 16 §1); "Vue's `provide`/`inject` is reactive" (cause: provided refs are; a plain value is read once, F10); "putting a service in React context is free" (cause: context looks like a global; every reader re-renders when the provided value changes identity, F6).
