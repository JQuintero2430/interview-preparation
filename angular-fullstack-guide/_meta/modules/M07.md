### 1. Generics: constraints, defaults, inference and `const` type parameters · ~550 words · SEC-M07-01
- **Problem:** a `first(items: any[])` helper returns `any`, so the bug flows downstream. With `unknown` every caller must cast.
- **Model:** a type parameter is a blank that each call fills in, and TypeScript fills it from the arguments.
- **Mechanism:**
  - type parameters on functions, interfaces and classes;
  - constraints (`T extends { id: string }`, `K extends keyof T`) and the error when they fail (`TS2345`/`TS2344`);
  - defaults (`<T = unknown>`);
  - inference sites: arguments, contextual typing of callbacks, return position does not drive inference;
  - `const` type parameters [5.0] and `NoInfer` [5.4];
  - the "a type parameter used once is a smell" guideline from the handbook ("Guidelines for Writing Good Generic Functions").
- **Verification:** `section-1-generics.test.ts` with `typecheck` codes and literal-type probes.
- **Callout:** *Coming from the backend*: Java generics with bounded wildcards versus TypeScript constraints. No `? super`; variance is structural (link §5).
- **Questions drilled:** Q07.01, Q07.02; Exercise 07.1.

### 2. `keyof`, indexed access, mapped and template literal types · ~550 words · SEC-M07-02
- **Problem:** a `getProp(obj, 'nmae')` typo compiles, and every `FormModel` must be rewritten by hand as `Partial`, readonly or getter versions.
- **Model:** types computed from other types, like a spreadsheet formula over a table's column names.
- **Mechanism:**
  - `keyof`, `T[K]`, `typeof value`, `(typeof arr)[number]`;
  - mapped types `{ [K in keyof T]: … }`, modifiers `readonly`/`?` and their removal with `-`;
  - key remapping with `as` [4.1], including filtering with `never`;
  - template literal types [4.1] and intrinsic string types (`Capitalize`);
  - homomorphic mapped types keep modifiers.
- **Verification:** `section-2-mapped-types.test.ts` with two-way assignability probes for each computed type.
- **Questions drilled:** Q07.03, Q07.04; Exercise 07.1.

### 3. Conditional types, distributivity, `infer` and recursive types · ~600 words · SEC-M07-03
- **Problem:** a function returns `string` for string input and `number` for number input, and overloads multiply.
- **Model:** a type-level `if`. Given a union, it runs once per member unless the check is wrapped.
- **Mechanism:**
  - `T extends U ? X : Y`;
  - distribution over naked type parameters, and `[T] extends [U]` to stop it;
  - `never` in, `never` out;
  - `infer` in return, parameter, array, promise and template positions;
  - recursive types (`DeepReadonly`, JSON) and their limits: the instantiation depth error `TS2589`, and how arrays and functions need their own branches.
- **Verification:** `section-3-conditional-types.test.ts`. The `TS2589` claim must be reproduced, or dropped.
- **Diagram:** one Mermaid flowchart (a distributive conditional over `A | B`: split, evaluate each member, union the results), followed by "What to notice".
- **Questions drilled:** Q07.05–Q07.07.

### 4. Utility types, built in and by hand · ~500 words · SEC-M07-04
- **Problem:** a DTO for "create" (no `id`) and one for "update" (all optional) drift from the entity.
- **Model:** the built-ins are ordinary mapped and conditional types that you could write yourself.
- **Mechanism:**
  - `Partial`, `Required`, `Readonly`, `Pick`, `Omit`, `Record`, `Exclude`, `Extract`, `NonNullable`, `ReturnType`, `Parameters`, `Awaited` [4.5];
  - their definitions read from `lib.es5.d.ts` in typescript 6.0.3 (quote the actual source);
  - `Omit` is not distributive over unions (`DistributiveOmit`);
  - `Omit<T, K>` accepts any `K extends keyof any` (a typo is not an error), and `Pick` does not accept one.
- **Verification:** `section-4-utility-types.test.ts`. Hand-written versions are compared with the built-ins by two-way assignability; the lib text is read from `node_modules/typescript/lib/lib.es5.d.ts`.
- **Questions drilled:** Q07.08, Q07.09.

### 5. Variance, parameter bivariance and `strictFunctionTypes` · ~500 words · SEC-M07-05
- **Problem:** a `(e: MouseEvent) => void` handler is stored where a `(e: Event) => void` is expected, and crashes on a keyboard event.
- **Model:** producers can be narrowed (covariant), consumers can be widened (contravariant).
- **Mechanism:**
  - arrays are covariant (unsound on write);
  - function parameters are contravariant under `strictFunctionTypes` (part of `strict`, module 06 §7), but **method-syntax** members stay bivariant (handbook / 2.6 notes);
  - `in`/`out` annotations [4.7] document and check variance and speed up comparison;
  - the `Array.prototype.push` hole.
- **Verification:** `section-5-variance.test.ts` (property-syntax vs method-syntax handler codes, `in`/`out` violations).
- **Questions drilled:** Q07.10, Q07.11.

### 6. Branded types for IDs and money · ~400 words · SEC-M07-06
- **Problem:** `cancel(orderId, userId)` with swapped arguments compiles (module 06 Q06.05), and cents are added to euros.
- **Model:** a brand is a type-only label stuck on a primitive. Nothing changes at run time.
- **Mechanism:**
  - `string & { readonly __brand: 'UserId' }`, or a `unique symbol` brand;
  - a constructor or validator function as the only way in (`as` lives in one place);
  - arithmetic loses the brand (`a + b` is `number`), so money operations go through functions;
  - brands versus classes and `#private` brands (link Q03.09);
  - Zod `.brand()` → §8.
- **Verification:** `section-6-brands.test.ts`.
- **Questions drilled:** Q07.12; Exercise 07.2.

### 7. Decorators: TC39 standard versus `experimentalDecorators`, and what Angular does with them · ~600 words · SEC-M07-07
- **Problem:** a team copies a decorator from an old library into a new project and it does not compile, or behaves differently. A colleague asks whether Angular 22 runs on "the new decorators".
- **Model:** a decorator is a function that the class definition calls with what it decorates. Angular's decorators are build-time annotations that its compiler reads and then removes.
- **Mechanism:**
  - standard decorators [Added in TypeScript 5.0]: `(value, context)` signature, kinds, `context.addInitializer`, evaluation order, no parameter decorators, the `accessor` keyword;
  - `experimentalDecorators` (the legacy, 2015-era semantics) and `emitDecoratorMetadata`;
  - decorator metadata [5.2] (check the notes before claiming it);
  - Angular: `experimentalDecorators: true` in the generated tsconfig. `ngc` replaces `@Component` with static `ɵfac`/`ɵcmp` and dev-only `ɵsetClassMetadata` (facts above), so decorator semantics matter only for parameter decorators (`@Inject`, `@Optional`, `TS1206` under standard decorators) and for your own decorators. Stage status and the TC39 proposal come from the proposal repo.
- **Verification:**
  - `section-7-decorators.test.ts` runs a standard method decorator and an `accessor` decorator, and asserts the logged order;
  - `typecheck` checks `TS1206` for a parameter decorator under standard decorators, without Angular, using a local stub;
  - the `ngc` observation is re-run and recorded in SOURCES.md as "observed by running";
  - an Angular spec asserts that a component class has static `ɵcmp` and `ɵfac` at run time (`labs/angular/src/app/modules/07-ts-advanced-types-and-decorators/decorators.spec.ts`).
- **Callout:** *Coming from the backend*: Java annotations are passive metadata read by reflection at run time; Angular's are read at build time and removed. **Where the analogy breaks:** standard JS decorators are functions that run, not passive metadata.
- **Questions drilled:** Q07.13–Q07.15.

### 8. Runtime validation with Zod 4: schema-first types · ~550 words · SEC-M07-08
- **Problem:** module 06's hand-written guard has to stay in sync with its interface by hand (Exercise 06.2's follow-up).
- **Model:** write the schema once; the type is derived from it (`z.infer`), and the run-time check is the schema itself.
- **Mechanism:**
  - `z.object`, `z.string()`, `z.number().int()`, optional and nullable fields;
  - `parse` (throws `ZodError`) versus `safeParse` (result object);
  - unknown keys: the Zod 4 default, `z.strictObject`, `z.looseObject`. Verify from the `.d.ts` and the docs, keeping 03's promise;
  - `.transform` and the input versus output types (`z.input`/`z.output`);
  - `.brand()` linking §6;
  - where to parse in an Angular app (the HTTP service boundary).
- **Install:** `zod@4.6.5` as an exact devDependency in `labs/ts-js` (facts above).
- **Verification:** `section-8-zod.test.ts` (run-time results and messages, plus `typecheck` with an extra file for `z.infer` types; resolving `zod` through the virtual consumer path inside `labs/ts-js/src`, as SEC-M06-08 did).
- **Callout:** *Framework vs platform*: Zod is a library, not part of Angular. The platform gives you nothing at run time.
- **Questions drilled:** Q07.16, Q07.17; Exercise 07.2.

### 9. Typing patterns in Angular code · ~600 words · SEC-M07-09
- **Problem:** `inject(CONFIG)` returns `any` from an untyped token; a form's `value.email` is `string | null | undefined` and nobody knows why; a generic list component loses its item type.
- **Model:** Angular's public APIs carry type parameters end to end. Your job is to supply the parameter once, at the source.
- **Mechanism:**
  - `new InjectionToken<T>(desc, { factory })`, so `inject(TOKEN)` is `T` (DI details → 16);
  - typed reactive forms [Angular 14]: `FormControl<T | null>`, `nonNullable`, `FormGroup<{…}>`, `getRawValue()` versus `value` (disabled controls make `value` `Partial`), `FormBuilder.nonNullable`, `UntypedFormGroup` for migrations;
  - `input<T>()`, `input.required<T>()` and `transform` inference (link Q17.27 for the signal side);
  - typed route data: `ResolveFn<T>` and component input binding (details → 24);
  - generic components: a component class with a type parameter inferred from its inputs in the template, under `strictTemplates`. Verify what Angular 22's template type-checker infers, and cite the docs.
- **Verification:**
  - Angular specs under `labs/angular/src/app/modules/07-ts-advanced-types-and-decorators/`;
  - type-level assertions as `// @ts-expect-error` lines, checked by `npx tsc -p tsconfig.spec.json --noEmit` (an unused directive is `TS2578`);
  - run-time assertions with `ng test`.
- **Questions drilled:** Q07.18–Q07.20; Exercise 07.3.

## Exercises (3, ceiling 4)

Each follows the full E1 anatomy. Compile-time criteria are checked with `typecheck` (ts-js), or with `tsc -p tsconfig.spec.json` and `@ts-expect-error` (Angular).

1. **Exercise 07.1 · A typed event bus** (EX-M07-01; sections 1 and 2). `createEventBus<Events extends Record<string, unknown>>()` with `on<K extends keyof Events>(type: K, handler: (payload: Events[K]) => void): () => void` and `emit<K extends keyof Events>(type: K, payload: Events[K])`. Criteria:
   - handlers receive their event's payload in registration order;
   - the returned function unsubscribes;
   - an unknown event name is a compile error;
   - a wrong payload type is a compile error;
   - an event whose payload is `void` can be emitted without an argument (a conditional rest-parameter type).
2. **Exercise 07.2 · Parse, brand and add money** (EX-M07-02; sections 6 and 8). A Zod schema for an API order (`id`, `customerId`, `lines` with `unitPrice` in minor units and `currency`) whose output brands `OrderId`, `CustomerId` and `Money`, and `addMoney(a, b)`. Criteria:
   - a valid payload parses to branded values;
   - an invalid payload gives a `ZodError` whose issues name the bad paths;
   - unknown keys are stripped (or rejected: decide and justify);
   - passing a `CustomerId` where an `OrderId` is expected is a compile error;
   - adding two currencies throws, and adding a raw `number` is a compile error.
3. **Exercise 07.3 · A typed settings form with a typed config token** (EX-M07-03; section 9; integrates 1, 2 and 4). In `labs/angular`: an `InjectionToken<SettingsDefaults>` with a factory, and a `SettingsForm` component whose `FormGroup` type is derived from a `Settings` interface by a mapped type (`ControlsOf<T>`), built with `nonNullable` controls. Criteria:
   - the form starts from the injected defaults;
   - `reset()` returns to the defaults, not `null`;
   - `getRawValue()` is typed `Settings` (an `@ts-expect-error` for a wrong field);
   - adding a field to `Settings` without a control is a compile error;
   - overriding the token in `TestBed` changes the defaults.
