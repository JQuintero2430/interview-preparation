### 1. Angular Elements: turning a component into a custom element · delta 850 (750 + 100 verification paragraph) · SEC-M37-01
- **Problem:** a CMS page, a server-rendered Spring/Thymeleaf screen or a React app needs one Angular widget (a rating, a price calculator) without becoming an Angular app; teams copy the code or embed an iframe.
- **Model:** `createCustomElement(Component, { injector })` returns a class the browser registers with `customElements.define('tag', Class)` (F2); from then on, any `<tag>` in the page, written by any code, becomes an Angular component: the browser calls the class's lifecycle callbacks and the class creates, updates and destroys the component (F3). The injector comes from `createApplication` (12 §6, link once): an application without a root component. Analogy: a power adapter: the wall socket is the browser's standard (custom elements), the appliance is the component, and the adapter maps one to the other. Diagram: `sequenceDiagram`: page → `customElements.define` → browser upgrades `<m37-rating>` → `connectedCallback` → strategy → `createComponent` → rendered.
- **Mechanism:** **read from the `@angular/elements` 22.2.1 source** (`fesm2022/elements.mjs`, `createCustomElement`, F2) to answer "why does the element need an injector": the strategy calls `createComponent` with an `environmentInjector` from it (F3). Use cases and non-cases: widgets in non-Angular pages, CMS embeds, gradual migration of an AngularJS or server-rendered app; **not** for components inside one Angular app (use the component), and not a micro-frontend architecture by itself (38). Each element bundle carries its Angular runtime once per application; several separately built bundles each carry their own (§3).
- **First-use definitions:** custom element, `customElements.define`, upgrade (link 08 §5), `createApplication`, environment injector (link 16 §7), Angular Elements.
- **Verification:** `labs/angular/src/app/modules/37-elements-pwa-errors-ecosystem/concepts/section-1-elements.spec.ts` (`ng test`): `Section 1: createCustomElement returns a class the registry accepts` (`customElements.define('m37-s1-hello', …)` then `customElements.get` is the class), `Section 1: an element created with document.createElement renders the component once connected` (text appears after `appendChild` and `ApplicationRef.tick`/`whenStable`, probe first), `Section 1: a property set before define reaches the component after upgrade` (probe first, F2); `labs/e2e/tests/37-elements-pwa-errors-ecosystem/concepts/section-1-host.spec.ts` (page `/host/hello.html`, plain HTML): `Section 1: a plain HTML page renders the Angular element without an Angular root`.

- **Misconceptions:** "Angular Elements turns the whole app into a web component" (cause: the name; it wraps **one** component per `define` call, F2); "a custom element built with Angular has no Angular runtime cost" (cause: it looks like a native tag; the bundle carries `@angular/core` and the application's providers, §3); "use the component's selector as the tag" (cause: it is the obvious name; the docs warn it creates two instances where Angular also matches the selector, F4).

### 2. The element's public contract: attributes, properties, events, projected content and typings · delta 700 · SEC-M37-02
- **Problem:** a host page sets `<m37-rating max-stars="5">` and the component sees the string `"5"`; a React wrapper listens for `rating-changed` and hears nothing; a parent `div` listener never fires; children added after the element connects never appear.
- **Model:** the element has four doors (F2, F3): **attributes** (strings, kebab-case, mapped from each input's template name), **properties** (any value, the input's name), **events** (each output becomes a `CustomEvent` named exactly like the output, value in `detail`, **not bubbling**), and **children** (projected into `<ng-content>` **once**, at creation). Analogy: a vending machine: coin slot (attributes: only one shape), card reader (properties: any value), the tray (events), and stock loaded once at install (children). Diagram: `flowchart LR`: host page → attribute / property → element → `setInput` → component; component output → `CustomEvent(detail)` → listener on the element.
- **Mechanism:** **read from the `@angular/elements` 22.2.1 source** (`observedAttributes` with `camelToDashCase`, `attributeChangedCallback`, the prototype accessors and the `CustomEvent` constructor, F2) to answer "why `maxStars` is `max-stars` but the event is `ratingChanged`"; input `transform` (`numberAttribute`, `booleanAttribute`) as the fix for string attributes (link 19 once); typings: `NgElement & WithProperties<{…}>` or `HTMLElementTagNameMap` augmentation (F4); the consumer side inside another Angular app: `CUSTOM_ELEMENTS_SCHEMA` lets the compiler accept unknown tags and properties, at the cost of no template checking for any unknown element (15:187 handoff; link 15 once at file level).
- **First-use definitions:** attribute versus property (link 08 §5), `CustomEvent`, `detail`, bubbling (link 08), content projection (link 19 §3), schema.
- **Verification:** `concepts/section-2-contract.spec.ts` (`ng test`): `Section 2: an attribute reaches a camelCase input through its kebab-case name`, `Section 2: an attribute arrives as a string unless the input has a transform` (probe first), `Section 2: an output is dispatched as a CustomEvent named after the output with the value in detail`, `Section 2: the output event does not bubble to a parent listener`, `Section 2: children present at connect are projected and children appended later are not` (probe first, F3); `concepts/section-2-schema.spec.ts`: `Section 2: a component with CUSTOM_ELEMENTS_SCHEMA compiles a template with an unknown element and property`.
- **Questions drilled:** Q37.02, Q37.03, Q37.04, Q37.05.
- **Misconceptions:** "outputs become kebab-case DOM events" (cause: inputs are kebab-cased for attributes; outputs keep the template name, F2); "a parent can listen for the element's event" (cause: DOM events from clicks bubble; `new CustomEvent` without `bubbles: true` does not, F2); "`CUSTOM_ELEMENTS_SCHEMA` is needed to define an element" (cause: both mention custom elements; the schema is for the **consumer's** templates only); "children update like `<ng-content>`" (cause: projection looks live inside Angular; Elements extracts projectable nodes once, F3).

### 3. Elements at run time: lifecycle, change detection without zone.js, styles and several apps on one page · delta 700 · SEC-M37-03
- **Problem:** an element moved in a sortable list loses its state; a property change from the host page does not re-render in a zoneless app; two widgets built separately both load Angular and their styles collide.
- **Model:** the element's lifecycle drives the component's (F3): connect creates (or cancels a pending destroy), disconnect **schedules** destruction 10 ms later, so a move within one task keeps the same component; an input set through the element calls `setInput` and notifies the scheduler, so change detection runs **without zone.js** (link 21 §5). Analogy: a hotel room held for a few minutes after checkout: come back quickly and your things are still there. Diagram: `stateDiagram-v2`: `defined` → `connected (component created)` → `disconnected (destroy scheduled)` → back to `connected` (cancelled) or → `destroyed`.
- **Mechanism:** **read from the `@angular/elements` 22.2.1 source** (`DESTROY_DELAY = 10`, `disconnect`, `connect`, `setInputValue` with `cdScheduler.notify`, `runInZone`, F3) to answer "why does a moved element keep its state" and "why does a zoneless element update"; styles: Emulated encapsulation adds attributes, `ShadowDom` puts styles inside the element (link 13 §9 once); several applications on one page each have their own injector and runtime copy (state it; F3's per-application injector); the docs' re-attach limitation (#38778, F4) quoted with the date.

- **Verification:** `concepts/section-3-runtime.spec.ts` (`ng test`, `provideZonelessChangeDetection()` in the test's environment): `Section 3: removing and re-adding the element within the delay keeps the same component instance` (fake timers, `vi.advanceTimersByTime(5)`), `Section 3: the component is destroyed after the destroy delay` (`vi.advanceTimersByTime(10)`; `ngOnDestroy` spy), `Section 3: a property set on the element re-renders without zone.js` (`await fixture.whenStable()` or `ApplicationRef.whenStable`, probe first); `labs/e2e/tests/37-elements-pwa-errors-ecosystem/concepts/section-3-runtime.spec.ts` (page `/host/two.html`): `Section 3: an element with ShadowDom keeps its styles out of the host page`.

### 4. `@angular/service-worker`: registration, `ngsw-config.json` and the generated `ngsw.json` · delta 750 · SEC-M37-04
- **Problem:** a hand-written service worker caches `main.js` forever and users run last month's build; another app registers its worker during startup and slows the first load.

Analogy: a librarian with a catalog card for each book's exact edition: if the edition changes, the card changes. Diagram: `flowchart LR`: `ngsw-config.json` → build → `ngsw.json` + `ngsw-worker.js` → browser registers (after stable or 30 s) → worker caches the listed files.
- **Mechanism:** **read from the `@angular/service-worker` 22.2.1 source** (`provideServiceWorker`, the strategy parsing and `Promise.race([appRef.whenStable(), delay])`, F5) to answer "why the default waits for stability"; disabled in development (`enabled: !isDevMode()`, F11; C9); HTTPS or `localhost` only (F12); `ngsw.json` must be served without long caching (F12). `#### Legacy`: `ServiceWorkerModule.register` (F5).
- **First-use definitions:** service worker, scope, registration (link 09 §9), `ngsw.json`, app version, `appData`.
- **Verification:** `labs/e2e/tests/37-elements-pwa-errors-ecosystem/concepts/section-4-registration.spec.ts`: `Section 4: the production build registers ngsw-worker.js and controls the page after a reload` (`swContext`, `waitForController`), `Section 4: ngsw.json lists hashed files and the appData from the config` (reads `/ngsw.json`, asserts `configVersion` 1, `appData.version` `v1`, a hash per file), `Section 4: a context with service workers blocked serves the same page without a controller`; `concepts/section-4-registration.spec.ts` (`ng test`): `Section 4: SwUpdate reports isEnabled false where the browser has no service worker` (F19).
- **Questions drilled:** Q37.09.
- **Misconceptions:** "the service worker runs during `ng serve`" (cause: it is in the app config; `enabled: !isDevMode()` and the builder's `serviceWorker` option are production-only by default, F11); "`ngsw-config.json` is the worker's runtime config" (cause: the name; the worker reads the generated `ngsw.json`, F10); "registration happens at bootstrap" (cause: `provideServiceWorker` sits next to other providers; the default strategy waits for stability or 30 s, F5).

### 5. Caching with asset and data groups, navigation requests and the app shell · delta 700 · SEC-M37-05
- **Problem:** an offline user sees the browser's dinosaur on a deep link; an API list is served stale for a day; a price is fetched from the network every time even though the user is offline.
- **Model:** **asset groups** are the app's own files, versioned with the app: `prefetch` downloads them at install, `lazy` on first use (`updateMode` decides what happens on a new version, F8); **data groups** are API responses, not versioned with the app: `performance` (cache first, `maxAge`) or `freshness` (network first, `timeout`, then cache) (F8; the strategies themselves are 09 §9's, link once); **navigation requests** (matching `navigationUrls`) get `index.html` (F8). Analogy: a pantry (asset groups: restocked when the menu changes) and a newspaper rack (data groups: kept for a set time, or always try for today's paper first). Diagram: `flowchart TD`: request → navigation? → `index.html` from the version; asset in a group? → version cache; data group? → strategy; else → network.
- **Mechanism:** **read from the `ngsw-worker.js` 22.2.1 source** (navigation detection with `navigationUrls`, the data group's `freshness` timeout path, `ngsw-bypass`, F7, F8) to answer "why does a deep link work offline"; `cacheOpaqueResponses`, `refreshAhead` and `applicationMaxAge` [Added in v19.0] one sentence each; the app shell: `ng generate app-shell` prerenders a shell route with server rendering (documented only, F11; the 32:2286 handoff, link 32).
- **First-use definitions:** asset group, data group, `installMode`, `updateMode`, navigation request, `ngsw-bypass`, app shell.
- **Verification:** `concepts/section-5-caching.spec.ts` (e2e, `swContext`): `Section 5: a deep link loads offline from the cached index.html`, `Section 5: a performance data group answers offline from the cache without reaching the server` (`hits`), `Section 5: a freshness data group goes to the network while online` (two loads, counter grows), `Section 5: a request outside every data group fails offline`, `Section 5: a request with ngsw-bypass skips the worker` (counter grows while a cached copy exists; probe first); offline through C10.
- **Questions drilled:** Q37.10, Q37.11.
- **Misconceptions:** "data groups are refreshed with each deployment" (cause: they sit in the same config; only asset groups are versioned, F8); "`freshness` means never stale" (cause: the name; after `timeout` or offline it serves the cache, F8); "the service worker caches every API call" (cause: it intercepts every request; only URLs in a data group are cached, F7).

### 6. Updates: versions, `SwUpdate`, prompting a reload, unrecoverable states and the kill switch · delta 750 · SEC-M37-06 (Opus)
- **Problem:** after a deploy, a support agent's tab keeps the old version for days; another app calls `activateUpdate()` and a lazy route fails with a missing chunk; a CDN caches `ngsw.json` and no one updates.
