### 3. Theming with Material 3: `mat.theme`, system variables, and light and dark with `color-scheme` · delta 750 · SEC-M36-03 (Opus)

### 4. Customizing the theme: system and component token overrides, and theming your own components · delta 650 · SEC-M36-04
- **Problem:** a designer wants a brand primary on buttons only, rounder cards and a custom card that matches Material in light and dark; the team overrides `.mdc-button__label` and it breaks on the next upgrade.
- **Model:** three levels, from safest to most fragile: **system overrides** (`mat.theme-overrides((primary: …))` changes `--mat-sys-*` for a subtree), **component overrides** (`mat.button-overrides((filled-container-color: …))` changes one component's tokens for a subtree; the mixin validates token names, F6), **direct CSS** on internal classes (unsupported across versions, F6 quoted). Your own components read `--mat-sys-*` (F6, `theming-your-components.md`) and expose their own custom properties (link Q13.25). Overrides follow inheritance: they reach what is inside the element they are applied to, and a dialog or menu renders outside it (§5), so overrides meant for overlays go on the overlay pane class or on `html` (probe first, C4). Analogy: changing the paint chart, repainting one appliance model, or scraping one appliance's enamel. Diagram: `flowchart TB` with three subgraphs `"system override"`, `"component override"`, `"direct CSS"`, each pointing to `"--mat-sys-*"`, `"--mat-button-…"` or `".mdc-… internal class"`, and a dashed edge `"overlay pane (outside the subtree)"` from the first two marked `"not reached"`. **What to notice:** the scope of an override is the DOM subtree, not the component tree.
- **Mechanism:** **read from the `@angular/material` 22.2.1 source** (`button/_button-theme.scss` `overrides` mixin, line 87, and the token-name validation it calls) to answer "why a misspelled token fails the build instead of silently doing nothing" (probe first: compile a misspelled override in a scratch Sass call under the test's temp dir, record the error, delete it; or drop the claim); strong focus indicators (`mat.strong-focus-indicators`, F5) in one paragraph with link 11 §4.

- **Verification:** `labs/e2e/tests/36-material-and-cdk/concepts/section-4-overrides.spec.ts` (page `/m36/overrides`): `Section 4: a component override changes only the buttons inside its subtree`, `Section 4: a system override inside a card does not reach a dialog opened from it` (probe first; the run wins), `Section 4: a custom card reads the system surface color in light and dark`.

### 5. Portals and overlays: where floating UI renders, how it is positioned and how it closes · delta 750 · SEC-M36-05
- **Problem:** a dropdown inside a card with `overflow: hidden` is clipped; a tooltip sits under a sticky header because of `z-index`; two stacked menus both close on one Escape; a menu stays open after navigation.
- **Model:** a **portal** is "content to render somewhere else" (a component, a template or an existing DOM node) and a **portal outlet** is "the place" (F10).
