### 4.2 The scan (HOUSE-41, HOUSE-42): `labs/tools/consistency-scan.mjs`

Node standard library only, a `node:test` file beside it, run only by main. Output is Markdown with no Markdown links (locations as `` `modules/NN-slug.md:line` ``), so it never touches the links gate. Sections:

1. **Non-canonical status markers** (HOUSE-41). Every `[…]` whose text starts with Developer preview, Experimental, Deprecated, Removed, Changed, Stable, Added or Baseline and does not match a STYLE-GUIDE §3.2 form. The canonical forms, as regular expressions over the bracket text: `Developer preview since v\d+(\.\d+)?`; `Experimental since v\d+(\.\d+)?`; `Deprecated since v\d+(\.\d+)? — use .+`; `Removed in v\d+(\.\d+)?`; `Changed in v\d+(\.\d+)?: .+`; `Stable since v\d+(\.\d+)?`; `Added in v\d+\.\d+`; `Baseline \d{4}: (newly|widely) available, per MDN`; `Baseline: limited availability, per MDN`. Grouped by shape (digits → N) with counts and locations. Fenced code is skipped.
2. **One API, different markers** (HOUSE-41). The API is the last backticked token within 60 characters before the marker on the same line. Groups the markers of each API across modules and reports every API with more than one distinct marker text of the same kind (two different `Stable since` versions) or of conflicting kinds (Deprecated in one module, Stable in another). An API marked in one module and unmarked in another is not reported (first-mention rules make that normal).
3. **Duplicate question candidates** (HOUSE-41). Every pair of `### Q` titles in different modules whose normalized titles are equal or whose token sets (lower case, backticks and punctuation dropped, tokens of 3+ characters, a small English stop list) have a Jaccard index ≥ 0.6. Lists both IDs, types and titles.
4. **Glossary terms defined in more than one module** (HOUSE-42). From GLOSSARY-TERMS.md, normalized as in §1 of this plan: the key and every module's full definition line, side by side.
5. **Header consistency** (HOUSE-42). Per module, the module numbers linked in `**Prerequisites:**` and `**Leads to:**` against the SYLLABUS §1 Prerequisites column: prerequisites missing or extra; a module X listing Y as prerequisite while Y's Leads to omits X. Plus each module's `**Applies to:**` line verbatim, for a version comparison against VERSIONS.md.

Flags: `--strict-markers` exits 1 when section 1 is not empty; otherwise exit 0. Main saves the output as `_meta/reviews/REVIEW-X-SCAN.md` (a generated file; a re-run overwrites it).
