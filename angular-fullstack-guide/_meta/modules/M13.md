**Template language, read from angular.dev (the docs footer says "Built by Angular at v22.2.1"):**
- F1. Expression syntax page (`/guide/templates/expression-syntax`): supported literals string, boolean, number, object, array, `null`, **RegExp**, template string, **tagged template string**; BigInt not supported. Globals: only `undefined` and `$any`; "no other JavaScript globals", examples `Number`, `Boolean`, `NaN`, `Infinity`, `parseInt`. Operators: arithmetic, `**`, ternary, `&&`, `||`, `!`, `??`, `typeof`, `void`, `in`, `instanceof`, spread in object/array literals, rest in calls, **arrow functions** ("must have an expression body"; "pipes cannot be used inside an arrow function"), and the non-standard pipe, optional chaining and `!`. Unsupported: all bitwise operators, destructuring, the comma operator, `new`, declarations (`let`, `const`, `function`, `class`, block-bodied arrow functions). "Assignment and increment/decrement operators are only valid in event listener statements" (unless inside an arrow function). Event handlers are statements (assignment yes, pipes no). A template variable shadows a class member; `this.` disambiguates.
- F2. Same page, "Safe navigation migration": "Prior to Angular 22, the optional chaining operator (`?.`) returned `null` when the left-hand side is null or undefined"; since 22 it returns `undefined`, as JavaScript does; the v22 `ng update` schematic added **`$safeNavigationMigration(foo?.bar)`**, "a temporary migration aid only … not a real function and cannot be called from TypeScript … may be removed in a future version". The function exists in `@angular/compiler` 22.2.1 (`fesm2022/compiler.mjs` lines 21980 and 31712: it throws "expects exactly one argument").
- F3. Binding page (`/guide/templates/binding`): interpolation converts every value to a string, "objects and arrays using the value's `toString` method"; property binding sets the DOM property (`[disabled]`), `[attr.role]` calls `setAttribute` and "if the value of an attribute binding is `null`, Angular removes the attribute"; interpolation inside an attribute or property is a property binding (`alt="Profile photo of {{ firstName() }}"`); `[class]` accepts string, string array or `Record<string, any>`; "Angular does not guarantee any specific order of CSS classes"; with an array or object, "Angular compares the previous value to the current value with `===`. You must create a new object or array instance"; space-separated names in one key are not supported (use `NgClass`); `[style]` accepts string or object; `[style.height.px]` units; collisions "follow its style precedence order" (the page does not state the order: Could not be read C3); ARIA: `[aria-label]` writes the string to the attribute and "removes it when the bound value is `null`"; structured ARIA values use property bindings.
- F4. Event-listeners page: `$event`; key modifiers `alt`, `control`, `meta`, `shift`; `keyup.enter`, `keyup.shift.enter`; **`code` suffix** `(keydown.code.alt.shiftleft)` ("the `key` property reports the character already modified by the Alt key", macOS `Alt + S` gives `ß`); global targets `window`, `document`, `body` (shown in `host`); "if the event handler statement evaluates to `false`, Angular automatically calls `preventDefault()` … Always prefer explicitly calling `preventDefault`"; custom event plugins through `EVENT_MANAGER_PLUGINS` (documented only).
- F5. Two-way-binding page: `[()]` "banana-in-a-box" combines `[]` and `()`; with `FormsModule`, `[(ngModel)]`; between components the child needs a `model()` and the parent binds a property **or a signal**. (The page does not show the desugaring: F27 observes it.)
- F6. Variables page: `@let` is "similar to the JavaScript `let`": one variable per block, value "kept up to date", cannot be reassigned (`(click)="value = value + 1"` invalid), scoped "to the current view and its descendants" and not hoisted (a nested `@let` is not visible outside its block); syntax `@let name = expression;`. Template reference variables: DOM element (including custom elements), component or directive instance, `TemplateRef` from `<ng-template>`; `#ref="exportAs"` for directives ("you cannot refer to a directive that does not specify an `exportAs`"); used with queries; a nested block reads outer references, never the reverse; "define a variable only once in the template".
- F7. Host-elements page: `host: { role, '[attr.aria-valuenow]', '[class.active]', '[style.background]', '[tabIndex]', '(keydown)' }`; global target prefixes `document:`, `window:`, `body:`; `(keydown.enter)` matches `KeyboardEvent.key` (layout dependent), `(keydown.code.Enter)` matches the physical key; "**Always prefer using the `host` property over `@HostBinding` and `@HostListener`. These decorators exist exclusively for backwards compatibility**"; "binding collisions": instance static beats host static; one static one dynamic: dynamic wins; both dynamic: **the component's host binding wins** (observed for properties and attributes, but **not for `class` and `style`**: F33); `[style.--my-background]` custom properties on the host; **`HostAttributeToken`** with `inject()` (throws when the attribute is missing unless optional).
- F8. Styling page (`/guide/components/styling`): four modes (Emulated, ShadowDom, **ExperimentalIsolatedShadowDom**, None); Emulated "generates a unique HTML attribute for each component instance, adds that attribute to elements in the component's template, and inserts that attribute into the CSS selectors"; global styles can still affect Emulated components; `:host` supported; "`:host-context()` is deprecated in modern browsers, [but] Angular's compiler provides full support" (the page's wording about browsers; Could not be read C2); Emulated "does not support any other pseudo classes related to Shadow DOM, such as `::shadow` or `::part`"; **`::ng-deep`**: "The Angular team strongly discourages new use of `::ng-deep`. These APIs remain exclusively for backwards compatibility", stops encapsulation "after that point in the selector" (Could not be read C1: no formal deprecation found); ShadowDom "impacts more than style scoping … event propagation, interaction with the `<slot>` API, and how browser developer tools show elements"; `ExperimentalIsolatedShadowDom` "strictly guarantees … global styles cannot affect elements in a shadow tree"; "In Emulated and ShadowDom modes, Angular doesn't 100% guarantee that your component's styles will always override styles coming from outside"; `<style>` in a template follows the component's mode and takes no bindings; `<link>` and `@import` are **external styles, "not affected by emulated view encapsulation"**; **CSS custom property namespacing**: `provideCssVarNamespacing()` with `APP_ID` (default `ng`), custom properties become `--my-app_primary-color`, opt-out prefix `--global--`, `CssVarNamespacer`, not applied to static `style=""`, object/string `[style]`, `Renderer2.setStyle`.
- F9. ### 1. Component anatomy: selector, template, styles, `imports` and the v22 file convention · ~750 words · SEC-M13-01
- **Problem:** a team copies a component and forgets to import its child: nothing renders and nothing fails; two components match the same button; nobody agrees on file names, so `user-card.component.ts` and `user-card.ts` live in one repository.
- **Model:** a component is **a class plus a template plus (optional) styles, bound to every DOM element that matches its selector**; that element is the **host element**, and the template renders inside it as the component's **view**. The `@Component` metadata is what the compiler reads to build the definition (12 §8, Q07.14). Analogy: a custom stamp: the selector is the pattern, every matching element gets stamped. Diagram: `flowchart TD`: `<lab-user-card>` host element (matched by selector) → view (template DOM) → child components; beside it the metadata fields (`selector`, `template`/`templateUrl`, `styles`/`styleUrl`, `imports`, `host`, `encapsulation`, `changeDetection`) as arrows to what each feeds. **What to notice:** one element is both "the component in the parent's template" and "the root of the component's own view".

- **Model:** encapsulation is **the compiler (Emulated) or the browser (ShadowDom) fencing a component's CSS**. Emulated **rewrites your selectors** so that each one also requires an attribute that only this component's elements carry; ShadowDom uses a real shadow root; None does nothing. Analogy: Emulated is a name tag on every guest plus rules that say "applies to guests wearing tag 7"; ShadowDom is a separate room with a door. Diagram: `flowchart LR`: component CSS + a per-type id → rewrite → `<style>` in head; the template's elements get `_ngcontent-<id>`, the host gets `_nghost-<id>`; beside it the ShadowDom branch (`attachShadow`, styles inside the shadow root). **What to notice:** nothing is isolated "inside"; the only difference between a scoped rule and a global one is an attribute selector (so specificity rises by one class-equivalent: module 10's line).
