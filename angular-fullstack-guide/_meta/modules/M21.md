## Facts established while planning (re-check in the task that uses them)

All dated 2026-10-09. **R** = ran under `ng test` in a scratch copy (Node 24.21.0, Angular 22.2.1, zoneless unless "zone"), **r** = read (installed `@angular/core` 22.2.1, the `v22.2.1` tag raw files, the zone.js 0.16.3 tarball, docs at `adev/src/content/…` of the tag), **c** = CHANGELOG line of `main` fetched the same day, attributed by the version heading it sits under. "Template ran" means a template method recorded its name.

*What marks a view dirty (R):*
- F1. **Inputs by reference.** `Parent` (signal `s`, plain `o = {n:1}`) binds `<p-ch [o]="o" />` (OnPush child, template `{{ t() }}{{ o().n }}`). After `o.n = 2` and `s.update(+1)`: the parent refreshed, the child did **not** run and the text stayed `1`; after `o = { n: 3 }` and another `s.update`: the child ran and showed `3`. Docs `skipping-subtrees.md`: new inputs compare "with `==`", in-place edits "preserve the reference" and trigger nothing (r).
- F2. **Event.** In `Host` (OnPush) = `<p-btn /><p-sib />` with `Btn` (OnPush, `(click)="c = c + 1"`) and `Sib` (Eager, plain field changed beforehand): after `button.click()` and `whenStable()` the templates of **`btn` and `sib` ran** and `sib` showed the changed field. Source: `wrapListener` calls `markViewDirty(startView, 5)` (`Listener`), which flags the view **and every ancestor** `RefreshView | Dirty` (bits 1024 | 64) when no refresh is in progress (r, `_debug_node-chunk.mjs`); a refreshed view checks its child components in `Global` mode, so the Eager sibling is refreshed and an OnPush sibling is skipped. Docs `skipping-subtrees.md` describe the same ("event in OnPush: change detection in the entire component tree … ignores OnPush subtrees outside").
- F3. **Async pipe.** `{{ s$ | async }}` over a `BehaviorSubject`: after `next('v1')` and `whenStable()` the template ran and showed `v1` (R). Source of the notification is 14 §8 (`markForCheck`; CHANGELOG 17.2.3 "AsyncPipe should not call markForCheck on subscription").
- F4. **Plain field + `markForCheck`.** A plain field changed with nothing else: no template ran and the text stayed `a`; after `cdr.markForCheck()` and `whenStable()` the text showed `b` (R).
- F5. **`setInput`.** `fixture.componentRef.setInput('v','new')`: the text was still `init` synchronously and `new` after `whenStable()` (R; `NotificationSource.SetInput`).
- F6. **Targeted refresh by signal.** Tree `Root` > `Par` (OnPush) > `Leaf`, and `Root` > `ParE` (**Eager**) > `Leaf`, all templates recording names: writing the leaf signal under `Par` ran **only `leaf.tpl`**; writing the leaf signal under the Eager `ParE` ran **only `leaf.tpl`** (R). Source: `REACTIVE_LVIEW_CONSUMER_NODE.consumerMarkedDirty` calls `markAncestorsForTraversal` (flag `HasChildViewsToRefresh` 8192 on ancestors, no refresh of them); `detectChangesInView` in mode `Targeted` (1) refreshes a view only if `RefreshView` is set or its reactive consumer is dirty and polls changed (r).
- F7. **`markForCheck` from a deep leaf** (same tree plus an OnPush sibling `sib`): `root.tpl`, `par.tpl`, `leaf.tpl` ran and the sibling `sib` did not (R); `markViewDirty(view, 4)` marks all ancestors `RefreshView | Dirty` (r). Contrast with F6: a signal refreshes the consumer only, `markForCheck` refreshes the path to the root. An `OnPush` sibling is skipped in both.
- F8. **Directive `ChangeDetectorRef`.** `inject(ChangeDetectorRef)` in a directive on a `<span>` inside `H`'s template: `markForCheck()` made **`H`'s template run** (R). Source `createViewRef(tNode, lView, isPipe)`: for a component host the component's own view, for an element, template, container or ICU node `lView[DECLARATION_COMPONENT_VIEW]` (the component whose template declares the node), `new ViewRef(hostComponentView, lView)` (r, `core.mjs`). Embedded-view and pipe forms are not run: the SEC task probes the embedded-view case or states it as read.
- F9. **Eager is not a trigger.** A component under an OnPush ancestor is not reached unless the ancestor is refreshed: zone probe, `Host` (OnPush) with an Eager child, timer in the zone writing the child's field: nothing rendered until the OnPush host was dirty (click) (R, zone). `detectChangesInView`: `CheckAlways` (16) refreshes only when `mode === 0` (Global), and `refreshView` always checks child components with mode 0 (r).

### 1. The synchronization problem: dirty checking and fine-grained reactivity · delta 800 (700 + 100 verification paragraph) · SEC-M21-01
- **Problem:** a counter changes and the screen must follow; three designs exist (re-check everything after any possible change, be told exactly what changed, rebuild and compare a tree); an Angular team lead asks why a click in a footer re-evaluates the page; a backend developer asks "is this a Hibernate flush?".
- **Model:** change detection is the step that makes the DOM match the state. Two answers: **dirty checking** (after anything that might have changed, compare each binding with its last value) and **fine-grained reactivity** (state announces who reads it, only those views are refreshed). Analogy: a night-shift inspector who walks every room and reads every meter versus meters that call the desk when the reading moves. Diagram: `flowchart LR` of "trigger → which views → compare bindings → write DOM" for both answers side by side. **What to notice:** both end with the same compare-and-write step; they differ in how a view is chosen. Link [17 §1](../../modules/17-signals.md#1-why-signals-exist) for the cost story; add only the new part: what a check is (F20: bindings evaluated for every refreshed view, DOM written only on difference, 0 mutations) and the two questions the rest of the module answers ("what tells Angular?" and "which views?").
- **Mechanism:** a check evaluates every binding expression of a refreshed view and writes the DOM only on a difference (F20, `Section 1: refreshing an unchanged view evaluates its template and writes nothing`; link [12 §8](../../modules/12-angular-how-it-works.md#8-under-the-hood-what-the-compiler-emits-and-what-the-runtime-does-with-it) for `bindingUpdated`); the two questions: the **trigger** (zone.js notification, or a signal/`markForCheck`/event notification: §3 and §5) and the **selection** (which views: §2 and §4); the v22 combination (zoneless default since v21, OnPush default since v22) in two sentences with markers; docs quotes on what zone.js cannot know (F23, docs only). Hibernate: persistence context as write-behind cache, flush translates state changes to SQL, `@Immutable` entities skip dirty checking (F27, C4).
- **First-use definitions:** change detection, dirty checking, binding, view, zone.js (link §3), OnPush (link §2), zoneless (link §5), fine-grained reactivity (link 17 §1), flush (link the Backend guide).
- **Verification:** `section-1-synchronization-problem.spec.ts`: `Section 1: refreshing an unchanged view evaluates its template and writes nothing` (F20, `MutationObserver`, template-run flag; assert "ran 3 times and 0 mutation records" only if repeated; otherwise `> 0` and `0`), `Section 1: a changed binding is the only DOM write` (a field changed then refreshed through a signal read by the same template, one `characterData` record). ### 3. zone.js and `NgZone`: how changes used to be detected, and why zone left the default · delta 950 · SEC-M21-03
- **Problem:** a chart library makes the page tick sixty times a second; a WebSocket callback updates a value and nothing renders; a bundle carries a polyfill that patches every async API; a new v21 project has no zone.js and a tutorial says "NgZone triggers change detection".
- **Model:** zone.js **monkey-patches** the browser's async APIs so every callback runs in a zone that knows when tasks start and end; `NgZone` is Angular's forked zone with `onUnstable`, `onMicrotaskEmpty`, `onStable`, and a subscriber that ticks when the microtask queue empties. `runOutsideAngular` leaves the zone, `run` re-enters. Analogy: a building where every door has a counter: when the last person leaves the lobby the inspector walks the whole building. Diagram: `sequenceDiagram` (browser event → patched `addEventListener` → angular zone → handler → `onMicrotaskEmpty` → `ApplicationRef.tick` → views checked). **What to notice:** the tick follows "something ran", not "something changed".

### 4. The tree walk: global and targeted refreshes · delta 850 · SEC-M21-04
