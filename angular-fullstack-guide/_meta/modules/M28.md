### 1. Kinds of state: server cache, UI, form, URL and session state, and where each belongs · delta 900 (800 + 100 verification paragraph) · SEC-M28-01

### 6. Effects: functional effects, flattening, error handling and `dispatch: false` · delta 750 · SEC-M28-06
- **Problem:** a search effect uses `mergeMap` and shows stale results; a save effect uses `switchMap` and loses writes; one failed request kills an effect for the rest of the session; an analytics effect dispatches its own action back and loops.

### 12. Under the hood: how NgRx Store reduces actions and how SignalStore keeps state in signals · delta 650 · SEC-M28-12
- **Problem:** an interviewer asks why `dispatch` updates the state synchronously, why a selector does not emit when an unrelated slice changes, and why `patchState` with the same value does not re-render.

Analogy: a conveyor belt with a stamping machine (Store) versus a wall of individual light switches (SignalStore). Diagram: `flowchart LR` with two lanes: `"dispatch"` → `"ActionsSubject"` → `"State: scan(reducer)"` → `"Store$"` → `"select (memoized)"`; `"patchState"` → `"compare per key"` → `"set changed key signals"` → `"computed / template"`. **What to notice:** NgRx Store pushes whole-state snapshots and filters with memoization; SignalStore pushes per key.
- **Mechanism:** **read from the `@ngrx/store` 22.0.1 source**: `ActionsSubject`, `ReducerManager`, `State` (the `scan`/`withLatestFrom` and the scheduler it uses: quote what the source shows) in `fesm2022/ngrx-store.mjs`; **read from the `@ngrx/signals` 22.0.1 source**: `patchState`, `STATE_SOURCE`, `notifyWatchers` (internal) in `fesm2022/ngrx-signals.mjs`; F17 (unchanged and unknown keys), F4 (20.0.0 per-key signals; "Once true: one `WritableSignal` held the whole state until NgRx 20.0").
