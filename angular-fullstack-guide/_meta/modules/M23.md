## Facts established while planning (re-check in the task that uses them)

All dated 2026-10-09. **R** = ran (Node 24.21.0, `rxjs` 7.8.2 via `require`, frames by `TestScheduler.run`, one frame per character), **R-ng** = ran under `ng test` in the scratch copy, **r** = read (installed packages; npm-packed older `rxjs` typings), **c** = CHANGELOG line of `rxjs` 7.8.2's `CHANGELOG.md` attributed by the version heading it sits under, **d** = docs (RxJS `7.x` branch `docs_app/content/…`; Angular `main` branch `adev/src/content/ecosystem/rxjs-interop/…`). Frame notation `v@n` is "value v at frame n", `C@n` complete, `E@n` error.

*Higher-order mapping (R, r, c, d):*
- F1. **The four operators on one input (R).** Outer `a-b-----c---|` (a@0, b@2, c@8, complete 12); each outer value v maps to `defer` of a cold inner `--x--y|` with x = v+'1', y = v+'2' (frames +2, +5, complete +6), logging inner subscribe (`subv`) and `finalize` (`finv`):
  - `switchMap`: `suba@0 fina@2 subb@2 b1@4 b2@7 finb@8 subc@8 c1@10 c2@13 C@14 finc@14` (the previous inner is torn down **before** the next subscribes; the result completes when the outer has completed **and** the last inner completed).
  - `mergeMap`: `suba@0 subb@2 a1@2 b1@4 a2@5 fina@6 b2@7 subc@8 finb@8 c1@10 c2@13 finc@14 C@14` (interleaved).
  - `concatMap`: `suba@0 a1@2 a2@5 fina@6 subb@6 b1@8 b2@11 finb@12 subc@12 c1@14 c2@17 finc@18 C@18` (b buffered until a completed).
  - `exhaustMap`: `suba@0 a1@2 a2@5 fina@6 subc@8 c1@10 c2@13 C@14 finc@14` (b dropped: it arrived while a was active).
  - `mergeMap(fn, 1)` gave the `concatMap` frames (`a1@2 a2@5 b1@8 b2@11 c1@14 c2@17 C@18`); `mergeMap(fn, 2)` on `abc|` with inner `---x|` gave `a@3 b@4 c@7 C@8` (c waited for a slot).
  - An inner error ends the whole result: `switchMap` with inner `-#` → `E@1`.
  - `finalize` of the last inner ran **after** the downstream complete (`C@14 finc@14`).
- F2. **`*All` forms and aliases (R, r, c, d).** On `a-b|` mapped to `-x-y|`: `switchAll` `a1@1 b1@3 b2@5 C@6`; `mergeAll` `a1@1 a2@3 b1@3 b2@5 C@6`; `concatAll` `a1@1 a2@3 b1@5 b2@7 C@8`; `exhaustAll` `a1@1 a2@3 C@4`. `flatMap === mergeMap` and `exhaust === exhaustAll` (R). Typings: `flatMap` "@deprecated Renamed to mergeMap. Will be removed in v8"; `exhaust` "Renamed to exhaustAll"; `combineAll` "Renamed to combineLatestAll" (r); CHANGELOG 7.0.0-beta.11 "exhaustAll: renamed `exhaust` to `exhaustAll`" (c). The `resultSelector` overloads of `switchMap`, `mergeMap`, `concatMap`, `exhaustMap` are `@deprecated … Use an inner map instead` in 7.8.2 and already in the 6.0.0 typings ("resultSelector is no longer supported, use inner map instead") (r); docs `deprecations/resultSelector.md`: "introduced in RxJS 6.0" (d). Markers: `exhaust` `[Deprecated since v7.0 — use exhaustAll]`; `flatMap` deprecated per typings (deprecation version not read: no version, C7); result selectors `[Deprecated since v6.0 — use an inner map]`.
- F3. **Promise and array inners (R).** `of(1,2,3).pipe(switchMap(v => Promise.resolve(v*10)))` → `[30]` (the synchronous source switched before the first promise settled); with `mergeMap` → `[10,20,30]`; `concatMap(v => [v, v])` → `[1,1,2,2]` (any `ObservableInput`).
- F4. **Recursive and accumulating flatteners (R, c).** `of(1).pipe(expand(x => x < 8 ? of(x*2) : EMPTY))` → `1@0 2@0 4@0 8@0 C@0`; with a cold inner `-b|`: `1@0 2@1 4@2 8@3 C@4`; `mergeScan((acc, v) => cold('-x|', acc+v), 0)` on `a-b|` (1, 2) → `1@1 3@3 C@4`; `switchScan` with a 3-frame inner on `a-b|` → `2@5 C@6`, on `ab|` with seed 10 → `12@4 C@5` (the switched-away accumulation never lands). CHANGELOG 7.0.0-beta.8 "switchScan: add switchScan() operator" → `[Added in v7.0]`.
- F5. **Source reads (r, `dist/esm/internal/operators`).** `mergeInternals(source, subscriber, project, concurrent, …)` keeps `buffer`, `active`, `index`, `isComplete`; `outerNext` subscribes when `active < concurrent`, otherwise `buffer.push`; on inner finalize it decrements `active`, shifts buffered values into new inner subscriptions, and `checkComplete` completes when `isComplete && !buffer.length && !active`; the `expand` flag re-feeds inner values. `mergeMap(project, resultSelector, concurrent = Infinity)`; `concatMap` is `mergeMap(project, 1)`. `switchMap` calls `innerSubscriber?.unsubscribe()` before subscribing the new inner and completes on `isComplete && !innerSubscriber`. `exhaustMap` ignores outer values while `innerSub` is set. All use `innerFrom` (converts any `ObservableInput`) and `createOperatorSubscriber` (internal).
- F6. **The wrong-operator bugs (R).** Out-of-order responses: `hot('a-b|')` with a slow inner for a (`-----A|`) and a fast one for b (`-B|`): `mergeMap` → `B@3 A@5 C@6` (stale A lands last), `switchMap` → `B@3 C@4`. Submit clicks `a-a-a------a|` with a 3-frame request: `exhaustMap` → `s@3 s@14 C@15`; `mergeMap` on `a-a-a|` → `s@3 s@5 s@7 C@8` (three posts).
- F7. **HTTP cancellation and completion (R-ng, r).** `terms.pipe(switchMap(t => http.get('/s?q=' + t)))` with `next('a')`, `next('ab')`: two requests (`/s?q=a`, `/s?q=ab`), `cancelled` `[true, false]`, result `['R-ab']`. A plain `http.get` completed once after one flushed response. `http.get('/r').pipe(retry(2))` with three 500 responses: 3 requests, then the error with `status` 500. Read in `@angular/common` 22.2.1 `fesm2022/_module-chunk.mjs`: the `FetchBackend` teardown calls `aborter.abort()` when the request is not done; the `HttpXhrBackend` teardown calls `xhr.abort()` when `readyState !== DONE`. `cancelled` is the testing backend's report, not a network observation (C5).

*Errors, retry and repeat (R, r, c):*
- F8. **`catchError` placement (R).** Outer `a-b-c|`, inner per value `x|` (value `A`, `B`, `C`), b's inner errors:
  - `catchError` **after** `switchMap`: `A@0 fallback@2 C@2` (complete at 2: the outer stream is gone, c is never processed).
  - `catchError` **inside** the inner pipe: `A@0 fallback@2`, then value `C` at 4 and complete at 5 (the outer stream survives).
  - `catchError(() => EMPTY)` on `a-#` → `a@0 C@2` (the error becomes a silent complete).
  - Rethrow: `catchError(e => throwError(() => new Error('wrapped:' + e.message)))` → `a@0 E:wrapped:orig@2`.
  - `catchError((err, caught) => caught)` re-subscribes the source: with `take(5)` on `a#`, 5 subscriptions and `a@0..a@4 C@4`; without `take` it never ends.
  - `take(1)` before an error: `a@0 C@0` (complete wins, the error never arrives). `onErrorResumeNextWith(x|)` after `a#` → `a@0 x@1 C@2`.
  - Source `catchError.js`: the selector receives `catchError(selector)(source)` as `caught`; the source subscription is unsubscribed before the handled result is subscribed (also for a synchronous error, `syncUnsub`) (r).
- F9. **`finalize` order (R, c).** `of(1).pipe(finalize(fin1), finalize(fin2))` → `next, complete, fin1, fin2`; on error → `error, fin`; on unsubscribe → `teardown, fin` (the source teardown first); with a completing source that returns a teardown → `complete, src teardown, fin`. CHANGELOG 7.0.0-beta.1 "finalize: callback will be called after the source observable is torn down" (c).
- F10. **`throwError` and `timeout` forms (r, c).** `throwError(value)` is `@deprecated Support for passing an error value will be removed in v8. Instead, pass a factory function` in the 7.0.0 and 7.8.2 typings and not deprecated in 6.6.7 (r); CHANGELOG 7.0.0-beta.5 "throwError: now accepts a factory" (c). Marker `[Deprecated since v7.0 — pass a factory]`. `timeoutWith` is `@deprecated Replaced with timeout` in the 7.0.0 typings (r); CHANGELOG 7.0.0-beta.4 "timeout: One timeout to rule them all" (c). Marker `timeoutWith` `[Deprecated since v7.0 — use timeout with a config]`.
- F11. **`retry` (R, r, c).** On a source `a#` (counting subscriptions): `retry(2)` → `a@0 a@1 a@2 E@3`, 3 subscriptions. `retry({ count: 3, delay: (err, n) => timer(2 ** n) })` on `#` → error at 14 (retries at 2, 6, 14), 4 subscriptions; `retry({ count: 2, delay: 5 })` → error at 10, 3 subscriptions. `resetOnSuccess`: a source failing after one value four times, then `b|`: `count: 2` → `E@3` after 3 subscriptions; with `resetOnSuccess: true` → `a@0 a@1 a@2 a@3 b@4 C@5`, 5 subscriptions. A delay notifier that **completes without emitting** (`EMPTY` on the second failure) completed the result silently: `C@1`, 2 subscriptions. `retry()` with no count retries forever (4 subscriptions until the fourth source succeeded). Source `retry.js`: `count = Infinity` default, `count <= 0` returns `identity`, `delay` number → `timer(delay)`, function → `innerFrom(delay(err, soFar))`, notifier complete → `subscriber.complete()`, `resetOnSuccess` zeroes `soFar` on `next` (r). CHANGELOG: 7.0.0-beta.0 "retry: add config to reset error count on successful emission", 7.3.0 "retry: Now supports configurable delay as a named argument", 7.0.1 "properly handles retry counts smaller than `1`" (c). Markers: `resetOnSuccess` `[Added in v7.0]`, `delay` option `[Added in v7.3]`.
- F12. **`repeat` (R, c).** `-a|` with `repeat(3)` → `a@1 a@3 a@5 C@6`; `repeat({ count: 3, delay: 4 })` → `a@1 a@7 a@13 C@14`; an error stops it (`-a#` → `a@1 E@2`). CHANGELOG 7.5.0 "repeat: now has configurable delay" (c). Marker `delay` option `[Added in v7.5]`.
- F13. **`retryWhen` and `repeatWhen` (r).** No `@deprecated` in the 7.2.0-7.5.0 typings; `@deprecated Will be removed in v9 or v10, use retry's delay option instead` (and the `repeat` equivalent) from 7.6.0 on (npm-packed typings compared). Markers `[Deprecated since v7.5.5 — use retry with delay]`, `[Deprecated since v7.5.5 — use repeat with delay]`. **Corrected 2026-10-09 (SEC-M23-04, re-checked by main with npm-packed typings): `@deprecated` is absent in 7.5.4 and present from 7.5.5, so the marker is `[Deprecated since v7.5.5 — …]`.**

*Multicasting (R, r, c):*
- F14. **`shareReplay` is `share` (r, `shareReplay.js`).** `share({ connector: () => new ReplaySubject(bufferSize, windowTime, scheduler), resetOnError: true, resetOnComplete: false, resetOnRefCountZero: refCount })`, `refCount` default `false`, `bufferSize` default `Infinity` (number argument or config object). CHANGELOG 6.4.0 "shareReplay: Add configuration object … `refCount`" (c) → `refCount` option `[Added in v6.4]`. `ReplaySubject` takes its clock from `dateTimestampProvider` (r, `ReplaySubject.js`).
- F15. **`shareReplay` runs (R, virtual time).** Over `interval(1)` with one subscriber leaving at 3: `shareReplay(1)` kept the source running (9 ticks by frame 10) and a subscriber arriving at 10 got the stale `8` first; `shareReplay({ bufferSize: 1, refCount: true })` stopped the source (2 ticks by 10) and the new subscriber got a fresh `0@11` from a second subscription. Over a source that completes (`--r|`): one subscription for two subscribers, the late one got `r` and `complete` at once, even with `refCount: true`. Over a source that errors first: the late subscriber started a new run (2 subscriptions) and got the success. `of(1,2,3).pipe(shareReplay(2))` subscribed twice: `a1 a2 a3 b2 b3`; `of(1,2,3).pipe(share())` twice: `a1 a2 a3 b1 b2 b3` (reset on complete re-runs).
- F16. **`ShareConfig` and `connect` (R, c).** `share({ connector: () => new ReplaySubject(1), resetOnError: false, resetOnComplete: false, resetOnRefCountZero: false })` over `a-b-c|`: a subscriber at 8 got `c` and complete. `share({ resetOnRefCountZero: () => timer(5) })` over `interval(1)`: a subscriber returning within the grace period continued the same run (`b3@4`), one after it got a fresh run (`c0@21`), 2 subscriptions in all. `source.pipe(connect(s => merge(s.pipe(filter(odd)), s.pipe(filter(even)))))` → `odd1@0 even2@2 odd3@4 C@5` with **1** source subscription; the same `merge` without `connect` subscribed twice. CHANGELOG 7.0.0-beta.10 "share: Make `share` completely configurable", "connect: Adds new `connect` operator"; 7.1.0 "share: use another observable to control resets"; 7.8.0 "ShareConfig factory properties now supports any `ObservableInput`" (c). Markers: `ShareConfig` `[Added in v7.0]`, `connect` `[Added in v7.0]`, reset notifiers `[Added in v7.1]`.

*Unsubscription and leaks (R-ng, r, c):*
- F17. **Strategies on destroy (R-ng).** A component whose sources are `defer(NEVER)` with `finalize` counters: after `fixture.destroy()`, the `toSignal`, `takeUntilDestroyed()` and `async`-pipe subscriptions were finalized; a raw `subscribe()` in the constructor was not (its finalize never ran). Source `fesm2022/rxjs-interop.mjs`: `takeUntilDestroyed` is `source.pipe(takeUntil(destroyed$))` where `destroyed$` nexts from `DestroyRef.onDestroy` (or at once if `destroyRef.destroyed`) (r). The mechanism is module 20's ([§5](../../modules/20-lifecycle-and-render-hooks.md#5-teardown-ngondestroy-destroyref-and-takeuntildestroyed)).

### 1. Higher-order Observables: `switchMap`, `mergeMap`, `concatMap` and `exhaustMap` · delta 900 (800 + 100 verification paragraph) · SEC-M23-01
- **Problem:** a search box maps each term to `http.get` and gets an `Observable<Observable<T>>`; nesting `subscribe` inside `subscribe` loses cancellation and error handling; four operators look alike and behave differently when a new value arrives while a request is running.
- **Model:** a **higher-order Observable** emits Observables; a **flattening operator** subscribes to each **inner** Observable and forwards its values into one output stream. Analogy: a phone receptionist: hang up and take the new call, put both on speaker, put the new caller on hold, or let it ring. ### 2. Choosing a flattening operator: races, lost writes, cancellation and recursion · delta 800 · SEC-M23-02
- **Problem:** a search list flickers to an older result; a double-clicked "Pay" posts twice; an autosave built with `switchMap` drops the edit that was in flight; a paginated API needs "fetch the next page until there is none".
- **Model:** pick by **what the work is**: a **query** whose old answers are worthless → `switchMap`; a **command** that must not run twice concurrently → `exhaustMap`; **ordered writes** → `concatMap`; **independent work** with a limit → `mergeMap(fn, n)`. Analogy: a kitchen: a re-ordered dish replaces the old ticket (switch), a "no second order until served" rule (exhaust), a queue of tickets (concat), a line of cooks (merge with n). - **Mechanism:** the race (F6: `mergeMap` lets a stale response land last); the double submit (F6); the lost write (`switchMap` unsubscribes an in-flight save, F1); **cancellation**: unsubscribing an `HttpClient` Observable aborts the request in the backend (F7 run with `HttpTestingController` `cancelled` and the `FetchBackend`/`HttpXhrBackend` source read; link 27, C5) and a Promise cannot be cancelled (link 04 §7, Q04.24); `expand` for pagination and its synchronous recursion (F4), `mergeScan` and `switchScan` `[Added in v7.0]` (F4).

### 3. Errors: `catchError` placement, `finalize`, and error versus complete · delta 850 · SEC-M23-03
- **Problem:** one failed search kills the typeahead for the rest of the session; a `catchError(() => EMPTY)` makes a stream end silently and nobody notices; a loading spinner stays on after an error; a `catchError` returning `caught` loops forever.
- **Model:** an **error** is terminal (22 §2's contract): after it, nothing upstream of the failure point runs again unless something re-subscribes. `catchError` **replaces** the failed stream with another one (a fallback, `EMPTY`, or a rethrow); **where** you put it decides **what** is replaced: after `switchMap` it replaces the whole stream, inside the inner pipe only the failed inner. `finalize` runs once, on complete, error **or** unsubscribe. Analogy: a fuse: put it on the branch circuit (inner) and only that room goes dark; on the main line (outer) the whole house does. Diagram: `flowchart LR` with two pipelines (catch outside, catch inside) and where the error stops. **What to notice:** catching inside keeps the outer subscription alive; catching outside ends it, gracefully but for good.
- **Mechanism:** the F8 runs (outer versus inner, `EMPTY`, rethrow with a factory, `caught` re-subscription, `take` before error, `onErrorResumeNextWith`); **read from the source** `catchError.js` (`caught` is `catchError(selector)(source)`, the source is unsubscribed before the replacement subscribes); `finalize` order (F9) and why it runs after the source teardown (CHANGELOG 7.0.0-beta.1); error versus complete for consumers (`firstValueFrom` rejects, `forkJoin` fails as a whole: links 22 §1, §7); `throwError(() => err)` versus the deprecated value form (F10); `config.onUnhandledError` is 22 §2's (one link).
- **First-use definitions:** terminal notification, fallback, rethrow, `EMPTY` (link 22 §6), `caught`, `finalize`, `onErrorResumeNextWith`, error factory.
- **Verification:** `section-3-errors.spec.ts`: `Section 3: catchError after switchMap ends the stream and inside the inner keeps it alive` (F8), `Section 3: catchError returning EMPTY completes silently` (F8), `Section 3: a rethrow replaces the error with a new one` (F8), `Section 3: returning caught re-subscribes the source` (F8, bounded by `take`), `Section 3: finalize runs after complete, after error and after unsubscribe, after the source teardown` (F9), `Section 3: take(1) completes before a later error` (F8), `Section 3: throwError with a factory creates the error at subscription` (F10: a factory counter).
- **Callouts:** `> [!WARNING]` `catchError(() => EMPTY)` at the end of a long-lived stream converts every failure into a silent completion (F8): log or surface the error before returning `EMPTY`.
- **`#### Legacy` (required):** `throwError(value)` `[Deprecated since v7.0 — pass a factory]` (F10), the `catch`/`finally` operator names of RxJS 5 (prototype-patch history: say "history, not in 7.8.2", verify absence by `grep` in the package before writing), with the current forms.

### 4. Retrying and repeating: `retry` with backoff and `repeat` · delta 750 · SEC-M23-04
- **Problem:** a flaky endpoint fails one request in twenty; retrying immediately hammers a struggling server; retrying a 400 is pointless; a dashboard must refresh after every successful load.
- **Model:** `retry` **re-subscribes after an error**, `repeat` **re-subscribes after a complete**. Each re-subscription to a cold source re-runs it (one more HTTP request, F7). The `delay` option turns a retry into a **backoff** (wait longer each time); a delay function can decide **whether** to retry by throwing (give up) or emitting (try again). Analogy: redialing a busy number: wait a little longer each time, give up after a few tries, and do not redial a wrong number. Diagram: `stateDiagram-v2`: `subscribed` → `error` → `waiting` (delay) → `subscribed` until the count is reached → `failed`; `complete` → `waiting` → `subscribed` for `repeat`. **What to notice:** both operators only re-subscribe; the source decides whether that repeats work.
- **Mechanism:** the F11 runs (counts, exponential delay frames, `resetOnSuccess`, a notifier that completes ends the stream silently, `retry()` forever); **read from the source** `retry.js` (`count`, `delay` number → `timer`, function → `innerFrom`, notifier complete → `complete`); `repeat` with count and delay (F12); filtering retryable errors by throwing from the delay function (`throwError(() => err)`); HTTP retry re-sends the request (F7: 3 requests); `retryWhen`/`repeatWhen` legacy (F13). Jitter is design advice (C9); link module 04's promise retry for the same idea without RxJS.
- **First-use definitions:** re-subscription, backoff, exponential backoff, jitter, retryable error, notifier (a stream whose emission triggers an action), `resetOnSuccess`.
- **Verification:** `section-4-retry.spec.ts`: `Section 4: retry(2) subscribes three times and then errors` (F11), `Section 4: retry with an exponential delay retries at frames 2, 6 and 14` (F11), `Section 4: resetOnSuccess restarts the count after a value` (F11), `Section 4: a delay notifier that completes ends the stream without the error` (F11), `Section 4: a delay function that throws gives up at once` (task probe first), `Section 4: retry re-sends an HttpClient request` (F7, `TestBed`), `Section 4: repeat with a delay re-subscribes after each complete and an error stops it` (F12).

### 8. Angular patterns: typeahead, polling, cache-then-network and racing requests · delta 850 · SEC-M23-08
- **Problem:** four features every Angular interview asks to sketch: a search box, a live dashboard, an offline-friendly list and a "fastest mirror wins" request; each fails in a specific way when one operator is wrong (a dead search after one error, overlapping polls, fresh data overwritten by cache, a fallback that never fires).
- **Model:** each pattern is a pipeline of decisions already taught: **typeahead** = rate (22 §8 `debounceTime`) + change filter (`distinctUntilChanged`) + query flattening (`switchMap`, §2) + per-request error recovery (inner `catchError`, §3); **polling** = a trigger (`timer`, or `repeat({ delay })` after each response) + command flattening (`exhaustMap`) + pause/stop (an on/off source with `switchMap` to `EMPTY`, `takeUntilDestroyed`) + retry (§4); **cache-then-network** = `concat`/`startWith` (ordered) versus `merge` (racing, can overwrite); **race** = `race` or `timeout({ first, with })`. Diagram: `flowchart LR` of the typeahead pipeline, one node per operator with the job it does. **What to notice:** removing any one node reintroduces one named bug.

### 9. Schedulers: queue, asap, async and animation frame, `observeOn` and `subscribeOn` · delta 750 · SEC-M23-09
- **Problem:** a test with `debounceTime` needs a fake clock; an animation wants values once per frame; a recursive source overflows the stack; a library delivers values synchronously during a component's constructor and somebody reaches for `observeOn` without knowing what it changes.
- **Model:** a **scheduler** decides **when** a piece of work runs and supplies the clock (`now()`). RxJS has four: `queueScheduler` (now, but trampolined: nested work runs after the current task), `asapScheduler` (a microtask), `asyncScheduler` (a timer: `setInterval`), `animationFrameScheduler` (before the next repaint). Without a scheduler, delivery is synchronous (22 §1). `observeOn` moves **delivery** of notifications onto a scheduler; `subscribeOn` moves the **subscription** (the producer's start). Analogy: a post office with four kinds of delivery: hand it over now but finish your current errand first, end of the current errand, a timed courier, and the next print run. Diagram: `sequenceDiagram` of one script turn: synchronous code, queue, microtasks (asap, promise), timers (async, `setTimeout`), animation frame, labelled with the F25 order. **What to notice:** asap shares the microtask queue with promises; async is a macrotask timer even with delay 0.
- **Mechanism:** the F25 order and trampoline; asap batching (one microtask flushes every queued asap action, read from `AsapAction` and `util/Immediate.js`); `AsyncAction` uses `setInterval` (F26) and fake timers count it (F19); `animationFrameScheduler` uses `requestAnimationFrame` (source read; jsdom only, C4); which operators default to `asyncScheduler` (F26 grep list) and that none defaults to `queueScheduler` (F26, C6); `observeOn` versus `subscribeOn` (F25 run, source read); the scheduler argument deprecated in favour of `scheduled` (F27); the scheduler is how §10 virtualizes time (link).
- **First-use definitions:** scheduler, task and microtask (link 04 §1), trampoline, macrotask, `requestAnimationFrame` (link 08), clock, `scheduled`.
- **Verification:** `section-9-schedulers.spec.ts`: `Section 9: schedulers run in the order sync, queue, asap, async` (F25 subset without `setTimeout` competition, awaited real timers), `Section 9: queueScheduler trampolines nested work` (F25), `Section 9: asap actions queued around a promise run in one microtask` (F25), `Section 9: asyncScheduler uses a timer even with delay 0` (F26: `vi.useFakeTimers`, `getTimerCount`), `Section 9: observeOn delays delivery and subscribeOn delays the producer` (F25), `Section 9: animationFrameScheduler runs on requestAnimationFrame` (jsdom, F25, C4), `Section 9: scheduled replaces the scheduler argument` (F27).
- **Callouts:** `> [!NOTE]` **Framework vs platform**: RxJS schedulers wrap platform queues (`queueMicrotask`-like promises, `setInterval`, `requestAnimationFrame`); Angular's zoneless scheduler (21 §5) is a different scheduler that decides when change detection runs (one sentence, link).
- **`#### Legacy` (required):** `of(1, 2, asapScheduler)`, `from(array, scheduler)` and `merge(a, b, scheduler)` `[Deprecated since v6.5 — use scheduled]` (F27) with `scheduled([1, 2], asapScheduler)` and `observeOn`.
- **Questions drilled:** Q23.31, Q23.32, Q23.33.
