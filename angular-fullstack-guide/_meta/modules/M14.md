**Read from angular.dev (page footer "Built by Angular at v22.2.1"):**
- F1. Directives overview (`/guide/directives`): three kinds (components, attribute directives, structural directives); "most effective when they encapsulate reusable behavior that you want to apply to an existing element or component"; "If you need to render your own markup … reach for a component"; the example directive uses `host: { '(mouseenter)': …, '[style.background-color]': … }` and a signal.
- F2. Attribute directives (`/guide/directives/attribute-directives`): "Angular's template syntax already covers changing a single element's classes, styles, properties, and events" (use bindings for one-off behavior); selector with brackets and an `app` prefix; the page injects `ElementRef` and sets `nativeElement.style.backgroundColor`; host events through `host`; `input()` named like the selector ("`[appHighlight]` both applies the directive and sets its value"); "Directives do not support namespaces"; `ngNonBindable` deactivates interpolation, directives and bindings for the children, "still lets directives work on the element where you apply" it.
- F3. Structural directives (`/guide/directives/structural-directives`): "applied to an `<ng-template>` element"; "For everyday conditional and repeated rendering, use Angular's built-in control flow blocks"; `*` is "transform[ed] … into an `<ng-template>`"; **"You can only apply one structural directive per element"** (use `<ng-container>`); microsyntax grammar (`let`, `as`, `keyExp`); translation rules: a naked expression binds `[prefix]`, a key binds `[prefixKey]` (PascalCase key appended to the selector), `let local` is `let-local="export"`, a `let` without assignment reads the context's `$implicit`; table: `*myDir="let item of [1,2,3] as items; trackBy: myTrack; index as i"` expands to `<ng-template myDir let-item [myDirOf]="[1,2,3]" let-items="myDirOf" [myDirTrackBy]="myTrack" let-i="index">`; a structural directive injects `TemplateRef` and `ViewContainerRef` and calls `createEmbeddedView(templateRef, { $implicit: data })`; guards: `ngTemplateGuard_(input)` (a type assertion function, or the literal type `'binding'` to narrow by truthiness) and `ngTemplateContextGuard` ("the guard body is not used at runtime, and included only to avoid TypeScript errors").
- F4. Directive composition API (`/guide/directives/directive-composition-api`): `hostDirectives` on components and directives; "Angular applies host directives statically at compile time"; "may not specify `standalone: false`"; "Angular ignores the selector of directives applied in the `hostDirectives` property"; inputs and outputs "are not included in your component's API by default": list them (`inputs: ['menuId']`) and alias them (`'menuId: id'`); transitive composition; **execution order**: host directive instantiated before the host, then both receive inputs, then host bindings apply host directive first ("components with `hostDirectives` can override any host bindings specified by a host directive"); DI: a host and its host directives may inject each other, "the providers defined by class with `hostDirectives` take precedence"; **de-duplication**: a template match wins and all host-directive matches of that directive are discarded; the same directive reached twice as a host directive is merged into one instance with merged mappings; two different aliases for one input are a compile error **`NG8024`**.
- F5. Pipes (`/guide/templates/pipes`): "By default, all pipes are considered pure, which means that they only execute when a primitive input value … or an object reference … is changed"; "mutations to object properties or array items are not detected unless the entire object or array reference is replaced"; a pipe needs a `name` and `transform`, should implement `PipeTransform`; naming conventions (camelCase name, `NamePipe` class); impure pipes: `pure: false`, "Avoid creating impure pipes unless absolutely necessary", a name containing `Impure` is a common convention; **"Pipes are not designed as injectable services"**: extract the logic into a function, import the function (examples with `toKebabCase`, `formatNumber`, `formatDate`, `formatCurrency`, `formatPercent`); precedence: the pipe operator "has lower precedence than other binary operators, including `+ - * / % && || ??`" and "higher precedence than the conditional (ternary) operator", so `isAdmin ? 'a' : 'b' | uppercase` parses as `isAdmin ? 'a' : ('b' | uppercase)`; built-in list: `AsyncPipe`, `CurrencyPipe`, `DatePipe`, `DecimalPipe`, `I18nPluralPipe`, `I18nSelectPipe`, `JsonPipe`, `KeyValuePipe`, `LowerCasePipe`, `PercentPipe`, `SlicePipe`, `TitleCasePipe`, `UpperCasePipe`; "Angular runs the pipes from left to right"; parameters follow colons (`date: 'hh:mm' : 'UTC'`). The page's code samples use `@Service()` for a service (module 16's topic, see F25).
- F6. `ng-template` page (`/guide/templates/ng-template`): a `TemplateRef` is obtained by a reference variable, a query or injection into a directive on the `<ng-template>`; rendered with `NgTemplateOutlet` or `ViewContainerRef.createEmbeddedView`; context through `let-name="key"` and the outlet's `ngTemplateOutletContext` or the second argument of `createEmbeddedView`; **"its injector context comes from the template declaration's location, not from where it is rendered"**; override with `ngTemplateOutletInjector` or the `injector` option; `ngTemplateOutletInjector="'outlet'"` inherits the outlet's injector (recursive trees).
- F7. Migration pages: `/reference/migrations/control-flow` ("Control flow syntax is available from Angular v17 … you don't need to import `CommonModule` anymore"; `ng generate @angular/core:control-flow`; breaking change: `@for` updates the bindings of a view whose tracked property changed with the same reference, `*ngFor` recreated it); `/reference/migrations/ngclass-to-class` (`ng generate @angular/core:ngclass-to-class`, "only usages that are considered safe"; `--migrate-space-separated-key`); `/reference/migrations/ngstyle-to-style` (`ng generate @angular/core:ngstyle-to-style`; `--best-effort-mode` can be unsafe "if the bound object is mutated").
- F8. Using DOM APIs (`/guide/components/dom-apis`): "Avoid direct DOM manipulation whenever possible. Always prefer expressing your DOM's structure in component templates and updating that DOM with bindings"; render callbacks (`afterEveryRender`, `afterNextRender`) "never run during server-side rendering"; "Never directly manipulate the DOM inside of other Angular lifecycle hooks" (layout thrashing); **`Renderer2`**: elements it creates take part in style encapsulation, `setProperty` and `listen` tie into synthetic animation properties/events, "Aside from these two narrow use-cases, there is no difference between using `Renderer2` and native DOM APIs. `Renderer2` APIs do not support DOM manipulation in server-side rendering"; legitimate DOM uses: focus, measuring geometry, reading text, native observers; "never directly set an element's `innerHTML`" (XSS; bindings sanitize).
- F9. Expression syntax (`/guide/templates/expression-syntax`): "Pipes cannot be used inside an arrow function, but you can pass an arrow function as an argument to a pipe."; i18n pipes page (`/guide/i18n/format-data-locale`): `DatePipe`, `CurrencyPipe`, `DecimalPipe`, `PercentPipe` use the `LOCALE_ID` token; a per-call locale argument overrides it.

### 1. Directives and attribute directives: host, inputs, `ElementRef` and `Renderer2` · ~850 words · SEC-M14-01
- **Problem:** a team writes a highlight directive that sets `el.nativeElement.style.color = 'red'` in its constructor; the template's `[style.color]` binding repaints the element blue and the directive "does nothing"; the same directive on an `<ng-template>` crashes because the "element" is a comment; a reviewer asks why the page uses `Renderer2` if the docs say it adds no safety.
- **Model:** a **directive** is **behavior attached to an existing element by a selector, with no template and no view of its own**; a component is a directive that owns a view (13 §1). Analogy: an accessory clipped onto a tool: it changes how the tool behaves, but the tool keeps its own body. Diagram: `flowchart LR`: `<button labBusy [labBusy]="saving()">` in the parent template → "selector matches" → one directive instance per matching element → three channels to the element (declarative `host` bindings and listeners; imperative `ElementRef`/`Renderer2`; inputs from the template), with a note on each: Angular orders and cleans the first, you own the second. **What to notice:** only the declarative channel takes part in change detection; an imperative write is overwritten by any binding that targets the same property.
- **Mechanism:** the kinds of directive (F1); `@Directive` metadata from the typings (F10): selector forms that must not cross element boundaries, `inputs`/`outputs` with aliases, `exportAs`, `providers`; **`host` metadata** is 13 §7's (one sentence; link Q13.21), used here for declarative behavior (F1, F2); an `input()` named like the selector lets one binding apply and configure the directive (F2) and `input(false, { transform: booleanAttribute })` makes a bare attribute true (`booleanAttribute` is core API: to assert); **aliases** with `input(…, { alias })`/`output(…, { alias })` (F39); `exportAs` plus `#r="name"` (13 §6 owns the reference; here the directive side); several directives on one element and one instance per matching element; no namespaces (F2); **`ElementRef`** is a thin wrapper whose `nativeElement` is `any` and whose typings carry `@security` (F10), and **on `<ng-template>` and `<ng-container>` it is a comment node** (F27); **`Renderer2`** is an abstract class that the DOM renderer implements (`NgClass` is built on it: F12); the docs' verdict: no difference from the DOM APIs except encapsulation attributes and animation hooks, and no SSR support for DOM manipulation (F8, C3); **why not touch the DOM directly**: (1) a binding on the same property overwrites the write (F27), (2) the docs state SSR and non-DOM renderers are not served (F8), (3) `innerHTML` and friends bypass sanitization and `ElementRef` is `@security`-tagged (F8, F10; link 33), (4) you own cleanup, ordering and hydration; **when DOM APIs are right**: focus, measuring, observers, always after render (`afterEveryRender`, link 20) (F8); `ng generate directive` writes `highlight.ts` with a standalone directive and the selector in brackets (F15, F41).
- **First-use definitions:** directive, attribute directive, selector (13 §1), host binding (13 §7), `ElementRef`, `Renderer2`, `exportAs`, alias, `nativeElement`, comment node (link 08), XSS (link 09/33), `afterEveryRender` (link 20).
- **Verification:** `section-1-attribute-directives.spec.ts` (`labs/angular`): `Section 1: host metadata and a signal input configure the host element`, `Section 1: a bare attribute is true through booleanAttribute`, `Section 1: exportAs lets a template reference read the directive instance`, `Section 1: input and output aliases use the template names`, `Section 1: Renderer2 writes are overwritten by a binding like direct writes`. The comment-node and overwrite claims are asserted by `Q14.03` and `Q14.04` in the Output spec and cited from there. Docs read and dated (F2, F8); `@security` and the `Renderer2` doc comment quoted from the typings (F10).
- **Callout:** *Framework vs platform* (`> [!NOTE]`, required): the element, `style`, `classList` and comment nodes are the platform's (module 08); Angular contributes the selector matching, the host bindings that it keeps current, and an indirection (`Renderer2`) that, per the docs, buys only encapsulation attributes and animation hooks.
- **Questions drilled:** Q14.01, Q14.02, Q14.03, Q14.04; Exercise 14.1.
- **Misconception candidates:** "`Renderer2` makes DOM access safe" (cause: the name suggests an abstraction layer; the typings say it provides no extra security, F10); "a directive can only live on elements" (cause: the name 'attribute directive'; it also matches `<ng-template>`/`<ng-container>`, where `nativeElement` is a comment, F27); "an attribute selector needs `*ngIf`-style imports to apply" (cause: unrelated to structural syntax; it must be listed in `imports` and **fails silently when missing**: 13 §1, link).

### 2. Structural directives: `ng-template`, `TemplateRef`, `ViewContainerRef` and the microsyntax · ~1,000 words · SEC-M14-02
- **Problem:** a team needs "render this only if the user may" in 40 templates and copies an `@if` with a service call; a developer writes `<p *labA *labB>` and gets a parser error; a custom directive's `let item` is typed `any`, so a typo in `item.nam` compiles.
- **Model:** a structural directive is **a directive on an `<ng-template>` that decides when, and how often, to stamp out the template**; the `*` is shorthand that wraps the element in that `<ng-template>`. The template is a **stencil** (it renders nothing by itself); `TemplateRef` is the stencil, `ViewContainerRef` is the place on the page where copies go, and each copy is an **embedded view**. Diagram: `sequenceDiagram` (Template, Compiler, Directive, ViewContainerRef): the parser expands `*labRepeat="n; let i = index"` into `<ng-template labRepeat [labRepeat]="n" let-i="index">`; the directive receives `TemplateRef` and `ViewContainerRef` by injection; an input changes; `createEmbeddedView(tpl, { index })`; later `clear()`. **What to notice:** the directive never touches the element inside the template; it only decides how many views exist and what context they get.

1. **Exercise 14.1 · A busy-state directive** (EX-M14-01; section 1; `labs/angular/src/app/modules/14-directives-and-pipes/exercise-1-busy-directive/busy.ts` + `busy.spec.ts`). `labBusy` (selector `[labBusy]`, `exportAs: 'labBusy'`): a signal input of the same name with `booleanAttribute`, an `isBusy` computed, host metadata only (`[attr.aria-busy]`, `[class.is-busy]`, `[attr.disabled]`, a `(click)` that is ignored while busy by calling `stopImmediatePropagation` **on the directive's own listener only**: the test registers a second template listener on a child element, not on the host, to keep ordering out of the criteria). Constraints: no `ElementRef`, no `Renderer2`, no `@HostBinding`; the solution's Alternative shows the `Renderer2` version and why it was not chosen; no forms API; the criterion about clicks uses an `output()` the directive emits (`activated`) only when not busy, so listener order is never asserted. Criteria:
   - `[labBusy]="true"` renders `aria-busy="true"`, `class="is-busy"` and a `disabled` attribute, and `false` removes all three;
   - a bare `labBusy` attribute is busy (the `booleanAttribute` transform);
   - `#b="labBusy"` exposes `b.isBusy()` to the template;

   - toggling the input back and forth leaves no duplicate classes and no stale attribute;

2. **Exercise 14.2 · A permission structural directive** (EX-M14-02; section 2; `exercise-2-allowed-directive/allowed.ts` + `allowed.spec.ts`). `*labAllowed="'admin'; else denied; let roles"`: inputs `labAllowed: string`, `labAllowedElse: TemplateRef<unknown> | null`; injects a small `CurrentRoles` class (a signal of roles); creates the embedded view when the role is present, the `else` template otherwise, and re-decides when the signal changes **without recreating the view when the answer stays the same**; context `{ $implicit: readonly string[]; role: string }` with an `ngTemplateContextGuard`. Constraints: at most two injected dependencies; no `ngIf` inside; the type guard is not asserted by a test (it is compile-time: the spec's AOT build type-checks a template that reads `roles.length` and `role.toUpperCase()`), the solution says so; no permission backend. Criteria:
   - the main template renders for an allowed role and the `else` template for a missing one;
   - changing the roles signal swaps the rendered template;
   - a change that keeps the answer `true` keeps the same DOM node (no recreation);
   - `let roles` reads the roles through `$implicit` and `role` reads the key through the context;
   - without an `else` template a denied user sees nothing and the container is empty;
   - destroying the host destroys the embedded view (a `ngOnDestroy` of a child in the template runs once).
3. **Exercise 14.3 · A menu button from host directives** (EX-M14-03; section 3; `exercise-3-menu-button/menu-button.ts` + `menu-button.spec.ts`). Two small directives declared in the same file, `labFocusRing` (host `[class.focus-ring]` on `focus`/`blur`, no inputs) and `labHint` (input `text`, host `[attr.title]`), and `lab-menu-button` with `hostDirectives: [labFocusRing, { directive: labHint, inputs: ['text: hint'] }]`, `host: { role: 'button', tabindex: '0' }`, a constructor log through a shared recorder. Constraints: no `extends`; no `NgModule`; DI only to read the host directive; the template-match case uses `labHint` applied in the host component's template as well. Criteria:
   - the host directives' constructors run before the component's and the recorder shows `focus-ring`, `hint`, `menu-button`;
   - only `hint` is exposed: `<lab-menu-button hint="Open">` sets the title, while `text="x"` stays a plain attribute and sets nothing;
   - the host element keeps the component's `role` and `tabindex` and the directive's class bindings after focus and blur;
   - `inject(labHint)` in the component returns the instance that owns the title;
   - the same directive written in the template (`<lab-menu-button labHint text="Both">`) is **one** instance: the recorder shows one `hint` constructor line and the template's input wins;
   - a second component that lists the same host directive with a different alias for the same input fails to compile (the test is a documented `// @ts-expect-error`-free note in the solution: the compile-time case is the dated `ngc` block of section 3, so the criterion list stays runtime-only).
4. **Exercise 14.4 · A search pipe, pure and impure, with an injected normalizer** (EX-M14-04; sections 5 and 7; `exercise-4-search-pipe/search.pipe.ts` + `search.pipe.spec.ts`). A plain function `search(items, term, normalize)`, a **pure** `labSearch` pipe and an **impure** `labSearchLive` pipe that both delegate to it and read a `SEARCH_NORMALIZER` token (default lower-casing) with `inject()`, plus a `computed` in a host component that uses the same function. Constraints: the pipes inject only the token; no pipe is injected into anything; counts come from a counting normalizer, never from timers; no `ngFor`. Criteria:
   - the pure pipe filters case-insensitively through the injected normalizer, and a different `SEARCH_NORMALIZER` provided by the host changes the result;
   - an unrelated signal change does not call the pure pipe again but calls the impure one;
   - an in-place `push` leaves the pure pipe's result stale and updates the impure one and **not** the computed (the signal was not notified);
   - replacing the array refreshes the pure pipe and the computed;
   - two usages of the pipe create two instances (a constructor counter);
   - the function is reused by the computed without injecting any pipe.
5. **Exercise 14.5 · A model of the `async` pipe** (EX-M14-05; sections 8 and 5; `labs/ts-js/src/modules/14-directives-and-pipes/async-pipe-model.ts` + `async-pipe-model.test.ts`). `createAsyncPipeModel<T>(host: { markForCheck(): void; reportError(e: unknown): void })` returns `{ transform(source: Subscribable<T> | PromiseLike<T> | null | undefined): T | null; destroy(): void }`. A **model of the behavior read in `AsyncPipe` 22.2.1 (F12), not Angular's pipe**; `Subscribable` is a structural type with `subscribe({ next, error })` returning `{ unsubscribe() }`, so there is no RxJS dependency. Constraints: no `ChangeDetectorRef`, no `untracked`, no zones; a non-promise non-subscribable value throws an `InvalidPipeArgumentError` whose message names the value. Criteria:
   - `transform(null)` returns `null` and subscribes to nothing;
   - the first call subscribes, returns the latest value (`null` until one arrives) and a later emission is returned by the next `transform` and calls `markForCheck` once;
   - a value emitted **synchronously during the first subscribe** is returned without calling `markForCheck`;
   - passing a different source unsubscribes the old one first, resets the value to `null`, and values the old source emits afterwards are ignored;
   - passing the same source again does not subscribe again;
   - `destroy()` unsubscribes and later emissions neither store a value nor call `markForCheck`;
   - an error goes to `reportError`, the last value stays, and promises are supported with the same rules;
   - a plain object or a function throws `InvalidPipeArgumentError`.
