- Key claims: [Doc: Java 25 API, `java.util` package summary and `Collection` (optional operations)]; [Doc: JEP 431]; R1 `M04 §1 · reversed() is a live view of a List`; R1 `M04 §1 · LinkedHashMap.putFirst moves an existing key to the front` (verify the exact `putFirst` semantics in src.zip); R2 `M04 §1 · getFirst does not compile on a Set` (verify the key, for example `compiler.err.cant.resolve.location.args`); R1 `M04 §1 · addAll returns false when nothing changed`.
- Diagram: classDiagram of the interface hierarchy, with `Sequenced*` interfaces and `Map` beside `Collection`.
- Callouts: **Version notes** (Java 1.2 framework; Java 5 generics and `Queue`; Java 6 `Deque`, `NavigableMap`; Java 9 `List.of`; Java 21 sequenced collections), each with its basis or dropped.

### §2. Lists: `ArrayList`, `LinkedList` and the legacy `Vector` and `Stack` · `SEC-M04-02` (M)
- Topics: `ArrayList` as a resizable `Object[]` (link 03 §6), default capacity 10 allocated lazily on first add, growth by half (`oldCapacity >> 1`, src.zip), `ensureCapacity`, `trimToSize`, `RandomAccess`; `add(i, e)`/`remove(i)` shift with `System.arraycopy` (O(n)); `modCount` increments on structural change (bridge to §7); `LinkedList` as a doubly linked list (`node(index)` walks from the nearer end), implements `Deque`, not `RandomAccess`; when `LinkedList` wins (rare: `ListIterator.add`/`remove` at a cursor, or used as a `Deque` where `ArrayDeque` cannot be used because of `null`s); `Vector` (synchronized methods, doubling growth, verify), `Stack extends Vector` (Javadoc recommends `Deque`); `List.remove(int)` vs `remove(Object)` with `List<Integer>`.
- Key claims: [Src: JDK 25 `ArrayList` `DEFAULT_CAPACITY`, `grow`, `elementData`]; [Src: JDK 25 `LinkedList.node`]; [Src: JDK 25 `Vector` growth, `Stack` Javadoc]; R1 `M04 §2 · remove(int) and remove(Object) on a List<Integer> remove different elements`; R1 `M04 §2 · LinkedList is not RandomAccess and ArrayList is`; R3 `M04 §2 · ArrayList capacity grows from 10 to 15` (verify in the task: child JVM with `--add-opens`, or `[Src]` only).

### §3. `HashMap` internals · `SEC-M04-03` (M)

- Key claims: [Src: JDK 25 `HashMap` `hash`, `putVal`, `resize`, `tableSizeFor`, `treeifyBin`, `newHashMap` `@since 19`]; [Doc: Java 25 API `HashMap` (load factor discussion)]; R1 `M04 §3 · a null key and null values are allowed`; R1 `M04 §3 · Hashtable rejects a null key and a null value`; R1 `M04 §3 · "Aa" and "BB" share a hash code` (collision seed for the callout); R3 `M04 §3 · the table doubles at the threshold and a colliding bin treeifies only at capacity 64` (verify in the task: child JVM with `--add-opens`, else `[Src]`).

- Topics: `Iterator` (`hasNext`, `next`, optional `remove` of the last returned element), for-each as sugar over `Iterator` (JLS §14.14.2) and the Iterator pattern (one sentence, link 51); `ListIterator` (cursor between elements, `previous`, `set`, `add`); fail-fast: `modCount` vs `expectedModCount`, checked in `next` (and `hasNext`? verify in src.zip), "best-effort" per Javadoc, so never relied on for correctness; CME on a single thread (removing in a for-each loop) and the second-to-last element case (`hasNext` returns false, no exception); `Iterator.remove`, `removeIf`, `ListIterator.set`; iteration order defined by the collection (row 07-16); weakly consistent (`ConcurrentHashMap`) and snapshot (`CopyOnWriteArrayList`) iterators, why "fail-safe" is a misleading name (→ 12).
- Key claims: [Src: JDK 25 `ArrayList.Itr` (`checkForComodification`, `cursor`, `lastRet`)]; [Doc: Java 25 API `ArrayList` (fail-fast best-effort sentence), `ConcurrentModificationException`, `java.util.concurrent` package summary (weakly consistent)]; [Doc: JLS 25 §14.14.2]; R1 `M04 §7 · removing in a for-each loop throws ConcurrentModificationException`; R1 `M04 §7 · removing the second-to-last element in a for-each loop does not throw`; R1 `M04 §7 · Iterator.remove and removeIf remove without an exception`; R1 `M04 §7 · a CopyOnWriteArrayList iterator does not see a later add` (no threads needed).
- Diagram: sequenceDiagram: loop → `hasNext` → `next` (`checkForComodification`) → `list.remove` (`modCount++`) → `next` → CME.
